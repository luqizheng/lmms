## 服务列表

| 服务 | 端口 | 说明 |
|------|------|------|
| **api-gateway** | 3000 | 统一入口，限流、鉴权、路由分发 |
| **config-service** | 8081 | 配置中心，键值存储 |
| **file-service** | 8082 | 文件上传、存储（挂载 `file-storage` volume）|
| **token-service** | 8082 | JWT RS256 签发、刷新、登出 |
| **iam-service** | 8081 | 身份与访问管理，用户/角色/权限 |
| **notification-service** | 8083 | 通知服务，支持邮件/WebSocket |
| **audit-service** | 8084 | 审计日志 |
| **prue-backend** | 8087 | Prueba 后端（MySQL + SQLite）|

## Outbox Pattern

`iam-service` 和 `notification-service` 各带一个 outbox publisher：

- `iam-outbox-publisher` — 从 MySQL outbox 表读取事件，推送到 RabbitMQ
- `notification-outbox-publisher` — 同上，用于通知服务的异步消息投递

这样做是为了保证**事件发送的原子性**：业务操作和 outbox 记录在同一事务，成功率 100%。

## 服务注册与发现

所有服务通过 **Consul** 注册自身，服务发现由 API 网关通过 Consul DNS 实现：
- 内部服务调用走 `http://<service-name>:8080`（Consul DNS 解析）
- API 网关的 `GW_CONSUL_ADDR` 指向 Consul 8500 端口
