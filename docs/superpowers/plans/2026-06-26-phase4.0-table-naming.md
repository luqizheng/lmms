# Phase 4.0 数据表命名规范统一 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把所有 Rust 服务共用 MySQL `superpowers` 库下的存量业务表，统一加服务前缀（`iam_/audit_/token_/ntf_/cfg_/file_/prue_`），消除 iam/audit `login_logs` 撞名隐患，并建立 CI gate + 文档规范防止回退。

**Architecture:** 单库（MySQL `superpowers`）多服务现状不动；通过表名前缀做逻辑隔离。每个服务新增 `V002__rename_tables.sql` + `V002__rename_tables.sqlite.sql`，同步在 `db.rs` 里增加 V002 应用块（沿用 prue_backend 现有 V001+V002 模式）。代码里所有 sqlx 查询同 commit 改名。`scripts/check-db-naming.js` 加 CI gate。

**Tech Stack:** Rust 1.96 + sqlx 0.8 + MySQL 8.0 + SQLite + Node.js 工具脚本

## Global Constraints

- 所有改动遵循已有项目约定（见 `agents.md` 与各 service 的 `AGENTS.md`）。
- 迁移文件命名沿用每服务现有格式：iam/audit/config/file/prue 用 `V{NNN}__<desc>.sql`（mysql/sqlite 子目录各一份），notification 用日期戳格式，token 用 sqlx 时间戳格式。
- 所有 SQL **必须包含幂等保护**（`CREATE TABLE IF NOT EXISTS` / `RENAME` 前先 `information_schema.tables` 探测），因为各服务的 `ensure_schema` 不是按版本号增量执行，多次启动可能重复触发。
- 表名前缀映射（与 spec §3 一致，硬性遵守）：
  - iam-service → `iam_`
  - audit-service → `audit_`
  - token-service → `token_`
  - notification-service → `ntf_`
  - config-service → `cfg_`
  - file-service → `file_`
  - prue_backend → `prue_`
- 索引/外键命名：`idx_<table>_<cols>` / `uk_<table>_<cols>` / `fk_<table>_<col>`。
- **绝对禁止**：在 4.0 范围内动列名、列类型、索引语义、外键关系；本 Phase 只重命名表。
- 任何 SQL 中 `DROP TABLE` 必须先做 `RENAME TABLE old TO new`，不允许真删数据。
- 工作环境：WSL/Linux/macOS（Windows 必须在 WSL）。所有 cargo / sqlx 操作走 `node scripts/run-tests-docker.js <svc>`。

- [ ] **Step 1: 写文档**

```markdown
# Database Naming Conventions

## 背景

所有 Rust 服务连接同一个 MySQL 实例的同一个 database `superpowers`。为防止跨服务表名冲突，统一约定如下规范。SQLite（prue_backend 单机 dev 模式）虽无共库问题，但同样遵循此规范以保持代码一致。

## 表名前缀映射

| 服务（crate）         | 前缀     | 示例                              |
| --------------------- | -------- | --------------------------------- |
| iam-service           | `iam_`   | `iam_users`、`iam_roles`          |
| audit-service         | `audit_` | `audit_login_logs`                |
| token-service         | `token_` | `token_refresh_markers`           |
| notification-service  | `ntf_`   | `ntf_announcements`               |
| config-service        | `cfg_`   | `cfg_namespaces`                  |
| file-service          | `file_`  | `file_files`                      |
| prue_backend          | `prue_`  | `prue_menu_configs`               |

> 与 `contracts/error-codes.yaml` 中的服务缩写（IAM/CFG/AUD/NTF/FILE/SYS）**故意不完全对齐**：错误码追求 3 字母短，表名追求可读，各自规则独立校验。

## 命名规则

- 表名：`<prefix>_<resource_plural_snake_case>`。例：`iam_users`、`audit_login_logs`、`ntf_announcement_recipients`。
- 索引名：`idx_<table>_<cols>`。例：`idx_iam_users_username`。
- 唯一键：`uk_<table>_<cols>`。例：`uk_iam_users_email`。
- 外键名：`fk_<table>_<col>`。例：`fk_iam_user_roles_user_id`。

## 不在规范内

- 列名、列类型、索引语义。
- 跨服务字段命名（每个服务自行约定）。
- 第三方组件自带表（sqlx migration metadata 等）。

## CI 检查

`node scripts/check-db-naming.js` 会扫：
- `services/*/migrations/**/*.sql`：所有 `CREATE TABLE` / `ALTER TABLE` 的表名必须以服务前缀起头。
- `services/*/src/**/*.rs`：所有 `sqlx::query*!` 宏与字符串里出现的表名必须以服务前缀起头。
- 例外白名单维护在脚本顶部（如 `_sqlx_migrations` 等系统表）。
```

`services/iam-service/migrations/mysql/V002__rename_tables.sql`：

```sql
-- Phase 4.0: rename iam tables to add iam_ prefix
-- Idempotent: skip if already renamed (table already named iam_users => done)
-- This file is applied by db.rs after V001's marker table check.

-- Use information_schema-guarded RENAME via stored procedure to avoid errors on re-run.
DELIMITER //
CREATE PROCEDURE IF NOT EXISTS phase40_rename_iam()
BEGIN
    DECLARE has_old_users INT DEFAULT 0;
    SELECT COUNT(*) INTO has_old_users
      FROM information_schema.tables
      WHERE table_schema = DATABASE() AND table_name = 'users';
    IF has_old_users > 0 THEN
        RENAME TABLE
            users            TO iam_users,
            roles            TO iam_roles,
            permissions      TO iam_permissions,
            menus            TO iam_menus,
            org_units        TO iam_org_units,
            user_roles       TO iam_user_roles,
            role_permissions TO iam_role_permissions,
            user_org_units   TO iam_user_org_units,
            refresh_tokens   TO iam_refresh_tokens;
        -- login_logs handled separately: see Task 3 (audit) for the disambiguation
    END IF;
END //
DELIMITER ;

CALL phase40_rename_iam();
DROP PROCEDURE IF EXISTS phase40_rename_iam;
```

> **关于 login_logs**: 根据 Task 0 baseline 决定 —— 若该表实际是 iam 的，则在上面 RENAME 列表里加 `login_logs TO iam_login_logs`；若是 audit 的，则在 Task 3 改名。**两个 task 各自只动归属自己的那个名字**，不能两边都写。

```rust
use sqlx::mysql::MySqlPool;
use crate::config::DatabaseConfig;
use tracing::{info, warn};

const INIT_SQL: &str = include_str!("../migrations/mysql/V001__init.sql");
const V002_SQL: &str = include_str!("../migrations/mysql/V002__rename_tables.sql");
const SCHEMA_MARKER_TABLE: &str = "users";
const V002_MARKER_TABLE: &str = "iam_users";

pub async fn connect(config: &DatabaseConfig) -> anyhow::Result<MySqlPool> {
    let pool = common::db::connect(&config.url, config.max_connections).await?;
    ensure_schema(&pool).await?;
    Ok(pool)
}

pub async fn ensure_schema(pool: &MySqlPool) -> anyhow::Result<()> {
    apply_v001_if_missing(pool).await?;
    apply_v002_if_missing(pool).await?;
    Ok(())
}

async fn apply_v001_if_missing(pool: &MySqlPool) -> anyhow::Result<()> {
    // V001 applied if either old marker `users` OR new marker `iam_users` exists.
    let row: (i64,) = sqlx::query_as(
        "SELECT COUNT(*) FROM information_schema.tables \
         WHERE table_schema = DATABASE() AND table_name IN (?, ?)",
    )
    .bind(SCHEMA_MARKER_TABLE)
    .bind(V002_MARKER_TABLE)
    .fetch_one(pool)
    .await?;
    if row.0 > 0 {
        info!("iam V001 schema present, skip");
        return Ok(());
    }
    info!("applying iam V001 schema");
    run_sql_script(pool, INIT_SQL, "V001").await
}

async fn apply_v002_if_missing(pool: &MySqlPool) -> anyhow::Result<()> {
    let row: (i64,) = sqlx::query_as(
        "SELECT COUNT(*) FROM information_schema.tables \
         WHERE table_schema = DATABASE() AND table_name = ?",
    )
    .bind(V002_MARKER_TABLE)
    .fetch_one(pool)
    .await?;
    if row.0 > 0 {
        info!("iam V002 already applied (iam_users present), skip");
        return Ok(());
    }
    info!("applying iam V002 rename");
    run_sql_script(pool, V002_SQL, "V002").await
}

async fn run_sql_script(pool: &MySqlPool, sql: &str, label: &str) -> anyhow::Result<()> {
    // Custom statement splitter: respect DELIMITER changes for stored procedures.
    // V002 uses DELIMITER //, so we can't split on plain ';'.
    // Strategy: execute the whole script as one batch via raw_sql.
    sqlx::raw_sql(sql).execute(pool).await.map_err(|e| {
        warn!(error = %e, label, "iam migration failed");
        anyhow::anyhow!("apply iam migration {label}: {e}")
    })?;
    info!(label, "iam migration applied");
    Ok(())
}
```

> 关键差异：V002 用了 `DELIMITER //`，原 db.rs 的 `split(';')` 会切坏 stored procedure。改用 `sqlx::raw_sql` 一次性执行整段。**V001 也跟着切到 raw_sql** —— 简化代码且兼容 MySQL 多语句。前提：数据库连接 URL 必须含 `multiStatements=true`（mysql8 默认允许 raw_sql；如不允许会在 step 5 测试时暴露）。

- [ ] **Step 1: 写脚本**

`scripts/check-db-naming.js`：

```javascript
#!/usr/bin/env node
// Phase 4.0 CI gate: enforce table-name prefix per service.
// See contracts/db-conventions.md

const fs = require('fs');
const path = require('path');

const PREFIX_MAP = {
  'iam-service':          'iam_',
  'audit-service':        'audit_',
  'token-service':        'token_',
  'notification-service': 'ntf_',
  'config-service':       'cfg_',
  'file-service':         'file_',
  'prue_backend':         'prue_',
};

// System tables / generic SQL keywords that look like table names but aren't ours
const ALLOWLIST = new Set([
  '_sqlx_migrations',
  'information_schema',
  'sqlite_master',
  'sqlite_sequence',
  'mysql',
  'performance_schema',
  'dual',
]);

let violations = 0;

function walk(dir, fn) {
  for (const entry of fs.readdirSync(dir, { withFileTypes: true })) {
    const full = path.join(dir, entry.name);
    if (entry.isDirectory()) walk(full, fn);
    else fn(full);
  }
}

function checkSql(svc, prefix, file) {
  const content = fs.readFileSync(file, 'utf8');
  // Match CREATE TABLE [IF NOT EXISTS] <name> and ALTER TABLE <name>
  const re = /\b(?:CREATE\s+TABLE\s+(?:IF\s+NOT\s+EXISTS\s+)?|ALTER\s+TABLE\s+)([a-zA-Z_][a-zA-Z0-9_]*)/gi;
  let m;
  while ((m = re.exec(content)) !== null) {
    const t = m[1].toLowerCase();
    if (ALLOWLIST.has(t)) continue;
    if (t.startsWith('_phase40')) continue;  // helper markers
    if (!t.startsWith(prefix)) {
      console.error(`[VIOLATION] ${file}: table "${t}" missing prefix "${prefix}"`);
      violations++;
    }
  }
}

function checkRust(svc, prefix, file) {
  const content = fs.readFileSync(file, 'utf8');
  // Match FROM/JOIN/INTO/UPDATE <table>
  const re = /\b(?:FROM|JOIN|INTO|UPDATE)\s+([a-z_][a-z0-9_]*)\b/g;
  let m;
  while ((m = re.exec(content)) !== null) {
    const t = m[1];
    if (ALLOWLIST.has(t)) continue;
    // Skip common rust keywords that match (rare but possible)
    if (['select', 'where', 'order', 'group', 'having'].includes(t)) continue;
    if (!t.startsWith(prefix)) {
      console.error(`[VIOLATION] ${file}: query references "${t}" missing prefix "${prefix}"`);
      violations++;
    }
  }
}

for (const [svc, prefix] of Object.entries(PREFIX_MAP)) {
  const migDir = path.join('services', svc, 'migrations');
  if (fs.existsSync(migDir)) {
    walk(migDir, f => f.endsWith('.sql') && checkSql(svc, prefix, f));
  }
  const srcDir = path.join('services', svc, 'src');
  if (fs.existsSync(srcDir)) {
    walk(srcDir, f => f.endsWith('.rs') && checkRust(svc, prefix, f));
  }
}

if (violations > 0) {
  console.error(`\n${violations} naming violations found. See contracts/db-conventions.md`);
  process.exit(1);
}
console.log('db naming check passed.');
```
