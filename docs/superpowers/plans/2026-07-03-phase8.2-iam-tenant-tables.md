# Phase 8.2 — iam-service 业务表 tenant_id 迁移 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给 iam-service 的业务表（`iam_roles` / `iam_org_units` / `iam_login_logs`）加 `tenant_id` 列，所有 tenant-owned 资源查询/写入改为 tenant-scoped，注册流程改为复制 per-tenant `tenant_admin` 角色模板，修复 8.1 遗留的 3 处硬编码 tenant_id 与 `/iam/users` 跨租户泄露。

**Architecture:** 共享 MySQL `superpowers` 库 + `tenant_id` 列（`BIGINT UNSIGNED` FK→`iam_tenants(id)`）。permissions/menus 全局不动；roles/orgs 改 tenant-scoped。列表查询用 `QueryBuilder` + `WithTenantScope::and_tenant`，点查询 bind `Principal.tenant_id`。注册流程同事务建 per-tenant 角色 + 全局权限 + 赋给 admin。iam 是 8.2 第一个服务，下游 audit/ntf/cfg/file 依赖它的 tenant 模型。

**Tech Stack:** Rust + axum + sqlx + utoipa + testcontainers(MySQL) + common-event outbox + jwt-ctx::Principal。

**Spec:** `docs/superpowers/specs/2026-07-03-phase8.2-tenant-business-tables-design.md`

## Global Constraints

- 本地 `cargo` 编不过，跑测试统一用容器：`node scripts/run-tests-docker.js iam-service`。
- forward-only 迁移：新增 `V004__tenant_business_tables.sql`，不编辑已发布迁移（但 V003 的 seed 角色用 V004 的 `UPDATE` 收归，不回改 V003）。
- iam 用**自定义迁移系统**（`src/db.rs::ensure_schema`，marker 表 + `include_str!` + `apply_sql_script` 按 `;` 切分），**不是** `sqlx::migrate!`。V004 必须在 `db.rs` 里接 marker + apply。`apply_sql_script` 会剔除 `--` 注释行、按 `;` 切语句，SQL 内不得出现 `;`（注释除外）。
- iam 迁移仅 **mysql**（无 sqlite 目录）。
- 表名前缀 `iam_`（`check-db-naming.js` 门禁）。
- `tenant_id` 类型 `BIGINT UNSIGNED`，iam 表 FK→`iam_tenants(id)`；`DEFAULT 1`。
- permissions 全局（不加 tenant_id）；roles/orgs tenant-scoped。
- 直接在 `main` 上工作，一个任务一个 commit，禁止 amend/force-push。Commit message：`feat(iam): ...` 或 `fix(iam): ...`。

```sql
-- Phase 8.2: tenant_id on iam business tables (roles / org_units / login_logs).
-- roles/orgs become tenant-scoped; permissions/menus stay global.

ALTER TABLE iam_roles
    ADD COLUMN tenant_id BIGINT UNSIGNED NOT NULL DEFAULT 1 AFTER code,
    ADD CONSTRAINT fk_iam_roles_tenant FOREIGN KEY (tenant_id) REFERENCES iam_tenants(id),
    ADD INDEX idx_iam_roles_tenant (tenant_id);

ALTER TABLE iam_roles
    DROP INDEX code;

ALTER TABLE iam_roles
    ADD UNIQUE KEY uk_tenant_role_code (tenant_id, code);

ALTER TABLE iam_org_units
    ADD COLUMN tenant_id BIGINT UNSIGNED NOT NULL DEFAULT 1 AFTER code,
    ADD CONSTRAINT fk_iam_org_units_tenant FOREIGN KEY (tenant_id) REFERENCES iam_tenants(id),
    ADD INDEX idx_iam_org_units_tenant (tenant_id);

ALTER TABLE iam_org_units
    DROP INDEX code;

ALTER TABLE iam_org_units
    ADD UNIQUE KEY uk_tenant_org_code (tenant_id, code);

ALTER TABLE iam_login_logs
    ADD COLUMN tenant_id BIGINT UNSIGNED NOT NULL DEFAULT 1 AFTER user_id,
    ADD INDEX idx_iam_login_logs_tenant (tenant_id);

UPDATE iam_roles SET tenant_id = 1 WHERE code = 'tenant_admin';

INSERT IGNORE INTO iam_role_permissions (role_id, permission_id, created_at)
SELECT 'role-tenant-admin-seed', id, NOW() FROM iam_permissions
WHERE status = 'enabled' AND deleted_at IS NULL
```

注意：末尾无 `;` 之外的语句内分号；`apply_sql_script` 会剔除 `--` 行并按 `;` 切分。MySQL 自动命名 `code` 列的 unique index 为 `code`，故 `DROP INDEX code`。
