# Phase 8.3-fu2 — ntf/cfg/file tenant hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close Phase 8.3 by migrating notification/config/file services to TenantScope + filling 8.2-stage gaps (config-service missing tenant layer, file-service V002 type migration).

**Architecture:** Three independent service sub-plans. ntf uses 8.3-fu1 pattern (point queries → QueryBuilder + and_tenant). cfg adds full tenant isolation layer missing since 8.2 + introduces Principal auth that didn't exist. file migrates VARCHAR(64) → BIGINT and drops SQLite. All services follow the `scope: &TenantScope` signature + `INSERT scope.tenant_id().unwrap_or(1)` pattern.

**Tech Stack:** Rust + axum + sqlx QueryBuilder + utoipa + testcontainers(MySQL) + jwt-ctx::TenantScope.

**Spec:** `docs/superpowers/specs/2026-07-04-phase8.3-fu2-ntf-cfg-file-tenant-hardening-design.md`

**Execution order:** ntf (smallest, most analogous to fu1) → file (type migration) → cfg (largest, has auth introduction).

## Global Constraints

- 本地 `cargo` 编不过，跑测试统一用容器：`node scripts/run-tests-docker.js <svc>`
- 直接在 `main` 上工作，一个任务一个 commit，禁止 amend/force-push
- 表名前缀：`ntf_` / `cfg_` / `file_`（check-db-naming.js）
- 服务方法全签名改 `tenant_id: i64` → `scope: &TenantScope`（Insert: `scope.tenant_id().unwrap_or(1)`）
- Handler 增 `TenantScope` extractor；cfg 同时增 `Principal`（首次引入 auth）
- testcontainers MySQL only（file-service drop sqlite，dev 不用 sqlite）
- check-tenant-scope.js exit 0（handler/service 委派 SQL 的函数加 `// check-tenant-scope: delegated` 注释）
- 沿用 `WhereTenantScope::{where_id, and_tenant}` from 8.3-fu1
- JOIN 场景 cfg `i JOIN n ON ...` 用 match 手写表名前缀（不扩 trait）
