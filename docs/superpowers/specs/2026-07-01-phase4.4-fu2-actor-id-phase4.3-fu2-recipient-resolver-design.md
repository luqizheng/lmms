## 2. iam 内部成员端点（用于 4.3-fu2）

### 2.1 端点契约

```
GET /iam/internal/users/by-role/{role_id}?page=1&size=100
GET /iam/internal/users/by-dept/{dept_id}?page=1&size=100
Authorization: Bearer <service-jwt>
```

### 2.2 响应

| Status | Body | 场景 |
|--------|------|------|
| 200 | `{ "items": ["<user_id>", ...], "page": 1, "size": 100, "total": <i64>, "truncated": false }` | 成功；truncated=true 表示 size>1000 被截断 |
| 400 | `"page must be >= 1"` / `"size must be 1..=1000"` | 参数越界 |
| 404 | `"role not found"` / `"dept not found"` | id 不存在或软删 |
| 401 | `"invalid or expired service token"` | token 无效、过期、缺 tid claim |
| 500 | `"internal error"` | 兜底 |

### 2.3 安全

- 走现有 `require_service_token` middleware（`.trae/rules/auth-rules.md`，token-service → iam 共用路径）。
- service-jwt 解码 `tid` claim → SQL 强制 `WHERE tenant_id = ?`。
- 不暴露给普通 token bearer；admin/non-admin 都拿不到。
- `page >= 1`，`size ∈ [1, 1000]`。超 1000 一律截断到 1000 + `truncated: true`，避免 DoS。
- 单次响应最大 1000 user_id，需要翻页由 caller 自处理（本期 publish_announcement 取 page=1, size=1000）。

### 2.4 SQL

```sql
-- /by-role/{role_id}
SELECT u.id
  FROM iam_users u
  JOIN iam_user_roles ur ON ur.user_id = u.id
 WHERE ur.role_id = ?           -- 整型 role.id
   AND u.deleted_at IS NULL
   AND u.tenant_id = ?          -- service-jwt tid
 ORDER BY u.id
 LIMIT ? OFFSET ?;
```

```sql
-- /by-dept/{dept_id}
SELECT u.id
  FROM iam_users u
 WHERE u.org_unit_id = ?        -- org_units.id
   AND u.deleted_at IS NULL
   AND u.tenant_id = ?
 ORDER BY u.id
 LIMIT ? OFFSET ?;
```

非整型 id 的传参（前端历史用 string id）由 service 层统一 `CAST` / 报错，本 spec 不涉及。

### 4.2 token refresh 策略

- 启动时拉一次 service token，缓存 `Arc<RwLock<String>>`
- 后台 tokio task 每 25 秒拉一次新 token，覆盖缓存

### 4.3 `db.publish_announcement` 重构

```rust
pub async fn publish_announcement(
    &self,
    ann_id: u64,
    iam_client: &IamMemberClient,
    tenant_id: i64,
) -> AppResult<Vec<String>> {
    let mut tx = self.pool.begin().await?;
    
    // 1) 锁行 + 状态守卫
    let row: Option<(String, String, i8, i8)> = sqlx::query_as(
        "SELECT title, status, pinned, popover FROM ntf_announcements WHERE id=? FOR UPDATE"
    ).bind(ann_id).fetch_optional(&mut *tx).await?;
    let (title, status, pinned, popover) = match row {
        Some(r) => r,
        None => { tx.commit().await?; return Ok(vec![]); }
    };
    if status == "published" || status == "revoked" {
        tx.commit().await?; return Ok(vec![]);
    }
    
    // 1.5) 提交锁 row（避免事务长期持有）
    tx.commit().await?;
    
    // 2) 拉 scopes + IAM 解析（tx 外，ResilientClient 包裹）
    let scopes = self.list_recipient_scopes(ann_id).await?;
    let user_ids: HashSet<String> = if scopes.is_empty() {
        HashSet::new()
    } else {
        iam_client.expand_scopes(&scopes, tenant_id).await?
    };
    
    // 3) 再开 tx 写 deliveries + status + enqueue（幂等 re-check）
    let mut tx = self.pool.begin().await?;
    let status_again: (String,) = sqlx::query_as(
        "SELECT status FROM ntf_announcements WHERE id=? FOR UPDATE"
    ).bind(ann_id).fetch_one(&mut *tx).await?;
    if status_again.0 == "published" || status_again.0 == "revoked" {
        return Ok(vec![]);
    }
    
    for uid in &user_ids {
        sqlx::query(
            "INSERT IGNORE INTO ntf_announcement_deliveries \
             (announcement_id, user_id, delivered_at) VALUES (?,?,NOW())"
        ).bind(ann_id).bind(uid).execute(&mut *tx).await?;
    }
    
    sqlx::query("UPDATE ntf_announcements SET status='published' WHERE id=?")
        .bind(ann_id).execute(&mut *tx).await?;
    
    let mut envelope = Envelope::new(
        "notification-service",
        NotificationAnnouncementPublished {
            announcement_id: ann_id as i64,
            title,
            pinned: pinned != 0,
            popover: popover != 0,
            user_ids: serde_json::json!(user_ids),
        },
    );
    self.outbox_repo.clone().enqueue(&mut tx, &mut envelope).await
        .map_err(|e| AppError::from(anyhow::anyhow!("outbox enqueue: {e}")))?;
    
    tx.commit().await?;
    Ok(user_ids.iter().cloned().collect())
}
```

**eventual consistency 接受**：tx 与 IAM 之间，`user→role` mapping 偶发变更（拉完后用户被移出某角色）→ 该用户本次不会收到，但下次 reload 会拉全集。无补救机制（不在本期）。

**幂等性**：二次 `FOR UPDATE` 锁即 recheck 状态。即使并发 publish：
- Step 1-1.5：第一个 caller 锁 + commit；第二个 caller 见 `status = "published"` → return。
- Step 3 recheck：同样护栏；竞态极端情况下两 caller 都进入 Step 3 → 行锁串行 → 第二人见 `published` → return。

**失败回滚**：
- Step 2 IAM 失败：`tx` 已 commit（锁释放）；Step 3 不进入 → `status` 不变 → caller 返 `ServiceUnavailable`，ann 仍为 `draft/scheduled`，可重试。
- Step 3 任一 INSERT/UPDATE 失败：tx rollback → `status` 不变 → caller 返错误。
