# Phase 8.3-fu2 — ntf/cfg/file 点查询迁移 + 8.2 漏做弥补

> 日期：2026-07-04
> 来源：`TODO.md` Phase 8.3 后续项「8.3-fu2 ntf/cfg/file 点查询迁移」+ 8.2 阶段漏做清单。
> 前置：Phase 8.3-fu1 已合并（where_id helper + iam 点查询 + handler TenantScope 全面贯通）。
> 范围：ntf 点查询 + cfg 8.2 漏做的 tenant 隔离层 + file V002 类型对齐 + tenant 隔离层。drop file 的 SQLite 支持。
>
> **已锁定的设计决策**（brainstorm 2026-07-04）：
> - D1 config-service **同时加 auth**（Principal extractor + 401 兜底）与 tenant 隔离
> - D2 file V002 走两步：UPDATE 兜底非数字值 → MODIFY COLUMN VARCHAR→BIGINT；**drop SQLite**（dev 期不用）
> - D3 沿用 8.3-fu1 模式：`scope: &TenantScope` 服务签名 + handler TenantScope extractor + INSERT `scope.tenant_id().unwrap_or(1)`

---

## 1. 背景与问题

8.3-fu1 闭环了 iam-service 的点查询 TenantScope 迁移，但仍有 3 个服务的点查询 / 8.2 阶段漏做项未结清：

- **notification-service**：`publish_announcement` 等点查询用固定 SQL `WHERE id=?`，**缺 tenant 过滤**（跨租户可改任意公告）；scheduler 从 DB 行读 tenant_id 后传入，逻辑不直观
- **config-service**：源码中**完全没有 `tenant_id` 概念**，handlers 不取 Principal；8.2 plan 写了 V002 但**从未实施**。Namespace 全局唯一，不同租户可看到/覆盖对方的命名空间
- **file-service**：8.2 plan 写了 V002（VARCHAR→BIGINT 类型对齐）但**从未实施**。Rust 模型 `tenant_id: Option<String>` 与全平台 `BIGINT UNSIGNED` 体系不一致；点查询同样缺 tenant 过滤

后果：跨租户访问漏洞（用户能按 id 改/删任何 tenant 的公告、配置、文件）。

---

## 2. 目标 / 非目标

### 目标

1. **ntf 点查询支持 TenantScope**：`publish_announcement` 的 SELECT/UPDATE 走 QueryBuilder + `where_id(ann_id)` + `and_tenant(scope)`
2. **cfg 补 8.2 漏做的 tenant 隔离层**：V002 migration 加 `cfg_namespaces.tenant_id` + 唯一键重建；Rust 模型 + handlers + service 全套 tenant 化；同步引入 Principal + TenantScope extractor（之前无 auth）
3. **file V002 类型对齐 + tenant 隔离**：VARCHAR→BIGINT 迁移；Rust 模型 `Option<String>`→`i64`；点查询走 QueryBuilder + `and_tenant`
4. **drop file SQLite 支持**：dev 期不用，减少 V002 复杂度（不必 rebuild table）

### 非目标

- prue_backend 的纯 SQLite 路线（prue_backend 是另一套，本来就是 V002 漏做的特例，未在 8.3-fu2 范围）
- cfg_config_items / cfg_config_versions / file_presign_urls 加冗余 tenant_id 列（FK 推导）
- notification-service 的 iam_client 内部迁移（仅其签名同步改 scope）

## 3. 设计

### 3.1 架构总览

```
┌─ notification-service ──────────────────────┐
│ REST publish: handler 取 Principal+TenantScope│
│   → service.publish_announcement(scope)      │
│ Scheduler: 从 announcement 行读 tenant_id    │
│   → 构造 TenantScope::Single(tid)            │
│   → service.publish_announcement(&scope)      │
│ 点查询: QueryBuilder + where_id + and_tenant │
└─────────────────────────────────────────────┘

┌─ config-service (8.2 漏做弥补) ──────────────┐
│ V002: cfg_namespaces.tenant_id BIGINT         │
│   UNIQUE → (tenant_id, app, env, profile)    │
│ handlers: 增 Principal + TenantScope         │
│ service: scope: &TenantScope 签名            │
│ 所有 SQL: 走 QueryBuilder + and_tenant       │
└─────────────────────────────────────────────┘

┌─ file-service (8.2 V002 漏做) ──────────────┐
│ V002: file_files.tenant_id VARCHAR→BIGINT     │
│   (drop SQLite, MySQL only)                  │
│ Rust model: Option<String>→i64               │
│ handlers: TenantScope extractor              │
│ point queries: QueryBuilder + and_tenant     │
└─────────────────────────────────────────────┘
```

### 3.2 notification-service

**`services/notification-service/src/db.rs::publish_announcement`** — 参数改：
```rust
pub async fn publish_announcement(
    &self,
    ann_id: u64,
    iam_client: &IamMemberClient,
    scope: &TenantScope,
```

内部 SELECT/UPDATE 走 QueryBuilder：
```rust
let mut qb = QueryBuilder::new("SELECT title, status, pinned, popover FROM ntf_announcements");
qb.where_id(ann_id);
qb.and_tenant(scope);
qb.push(" FOR UPDATE");
let row: Option<...> = qb.build_query_as::<...>().fetch_optional(&mut *tx).await?;
```

**`services/notification-service/src/rest.rs::publish_announcement` handler**：
```rust
async fn publish_announcement(
```

### 3.3 config-service（8.2 漏做补完）

**V002__tenant_cfg.sql（MySQL only）**：
```sql
ALTER TABLE cfg_namespaces
    ADD COLUMN tenant_id BIGINT UNSIGNED NOT NULL DEFAULT 1 AFTER id,
    ADD INDEX idx_cfg_namespaces_tenant (tenant_id),
    DROP INDEX uk_cfg_namespaces_app_env_profile,
    ADD UNIQUE KEY uk_cfg_ns_tenant_app_env_profile (tenant_id, app, env, profile);
-- cfg_config_items / cfg_config_versions：靠 namespace FK 推导，不加冗余列
```

**`models/namespace.rs`** — 加字段：
```rust
pub struct Namespace {
    pub id: String,
    pub tenant_id: i64,
    pub app: String,
    ...
}
```

**handlers (`routes/namespace.rs`)** — 加 Principal + TenantScope：
```rust
async fn create_namespace(
    State(state): State<AppState>,
    Principal { user_id, .. }: Principal,
    scope: TenantScope,
    Json(mut ns): Json<CreateNamespace>,
) -> ... {
    let tenant_id = scope.tenant_id().unwrap_or(1);
    ns.tenant_id = tenant_id;
    let result = state.create_namespace(ns).await...?;
}
async fn get_namespace(
    State(state): State<AppState>,
    scope: TenantScope,
    Path(id): Path<String>,
) -> ... {
    let result = state.get_namespace(&id, &scope).await...?;
}
// query / update / delete / list 同模式
```

**services / db** — service 方法签名 `scope: &TenantScope`；SQL 走 QueryBuilder + `where_id` + `and_tenant`：
```rust
pub async fn get_namespace(&self, id: &str, scope: &TenantScope) -> AppResult<Namespace> {
    let mut qb = QueryBuilder::new("SELECT ... FROM cfg_namespaces");
    qb.where_id(id);
    qb.and_tenant(scope);
    qb.push(" AND deleted_at IS NULL");  // 若有 soft delete
    qb.build_query_as::<Namespace>().fetch_optional(&pool).await?
}
```

**config_items / versions** 通过 namespace JOIN 加 tenant 过滤（手写拼 SQL 片段，因 `and_tenant` helper 不带表名前缀）：
```rust
// get_config_item
let mut qb = QueryBuilder::new(
    "SELECT i.* FROM cfg_config_items i JOIN cfg_namespaces n ON i.namespace_id = n.id WHERE i.id = "
);
qb.push_bind(id);
match scope {
    TenantScope::Single(tid) => {
        qb.push(" AND n.tenant_id = ").push_bind(*tid);
    }
    TenantScope::CrossTenant => {}
}
qb.push(" AND i.deleted_at IS NULL");
```

注：现有 `WithTenantScope::and_tenant` 默认拼 `AND tenant_id = ?`（无表名前缀）。JOIN 场景用 match 手写；若多处需要可后续扩展 trait 加 `and_tenant_aliased(alias)` 方法。本期不做 trait 扩展，避免 common-db 改动面扩张。

## 4. 数据流

### ntf publish（REST）
```
acme_admin → POST /notification/announcements/{id}/publish
  → Handler: scope = TenantScope::Single(7)
  → service.publish_announcement(id, &iam_client, &scope)
    → QueryBuilder::new("SELECT ... FROM ntf_announcements")
    → .where_id(id)
    → .and_tenant(&scope)  → AND tenant_id = 7
  → 仅 acme 的公告可发布；globex 公告 404
```

### ntf publish（scheduler）
```
scheduler loop:
  → 扫描 scheduled 公告（任意租户）
  → SELECT tenant_id FROM ntf_announcements WHERE id=? → 7
  → 构造 TenantScope::Single(7)
  → publish_announcement(id, &iam_client, &scope)
  → 仅当原公告属 tenant=7 时 publish 成功（防止 scheduler 误发/跨租户）
```

### cfg 跨租户隔离
```
acme_admin → POST /config/namespace { app:"api", env:"prod", profile:"x" }
  → 创建 cfg_namespace with tenant_id=7
globex_admin → GET /config/namespace/{acme_namespace_id}
  → service.get_namespace(id, &TenantScope::Single(globex_tid))
  → AND tenant_id = globex_tid → 0 行 → 404
```

### file 跨租户隔离
```
acme_admin → POST /file/upload (file metadata)
  → INSERT INTO file_files (..., tenant_id=7)
globex_admin → GET /file/{acme_file_id}
  → service.get_file(id, &TenantScope::Single(globex_tid))
  → AND tenant_id = globex_tid → 0 行 → 404
```

## 6. 风险

| 风险 | 严重度 | 缓解 |
|------|-------|------|
| cfg 加 auth 破坏不传 token 的现有调用 | 中 | svc-mesh 已 intentions + frontend 已传 token；非 frontend 调用方（如 seed 脚本）需补 token |
| file V002 类型迁移遇存量非数字 | 低 | dev 期无数据 + UPDATE WHERE NULL/空值兜底 |
| drop sqlite 破坏 dev 期 sqlite 路径 | 低 | 当前 dev 用 MySQL（`pnpm run dev:infra`），sqlite 仅为理论兼容；file-service 本来支持度低 |
| notify scheduler TenantScope 构造 | 低 | 仅 Single 分支，无 CrossTenant 路径，简洁 |
| cfg JOIN namespace 时 and_tenant 拼表名前缀 | 低 | QueryBuilder 直接 `push(" AND n.tenant_id = ").push_bind(*tid)` 即可，无需新 trait |
