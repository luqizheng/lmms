## 1. 背景

当前平台依赖 4 项基础设施（MySQL / Redis / Consul / RabbitMQ），均为**单容器单副本**，无自动备份。P0-4 第一阶段只做**备份 SOP 文档**（本 spec 的产出），不改变基础设施架构。HA 部分（主从、哨兵、多副本）写在 Roadmap 2.0，本 spec 不涉及。

## 2. 范围

本 spec 交付一个 runbook：`docs-site/runbooks/backup.md`，包含 4 种组件的**完整备份与恢复操作步骤**。

### In scope

- MySQL：`mysqldump` 全量备份 + `mysql` 恢复
- Redis：`SAVE`/`BGSAVE` RDB 文件备份 + 拷贝恢复
- RabbitMQ：`rabbitmqctl export_definitions` / `import_definitions`
- Consul：`consul snapshot save` / `consul snapshot restore`
- 每种组件的：备份命令、频率建议、保留策略建议、恢复步骤、验证方法
- 灾难恢复假设：数据组件在同一台机器 / 同一 `docker volume`

### Out of scope

- 自动备份脚本 / cron job（只写手动 SOP，自动化为后续工作）
- 异地备份 / 对象存储上传（只写本地文件拷贝建议）
- MySQL 主从搭建（属 HA，归 Roadmap 2.0）
- Redis Sentinel / Cluster（同上）
- Consul 3 节点集群（同上）

## 3. 设计方案

### 3.1 文件结构

```
docs-site/runbooks/backup.md       ← 本 spec 产出
```

`docs-site/runbooks/` 已有 5 个 runbook，本次不另建索引（备份 runbook 自包含）。

### 3.2 格式约定

每个组件一节，分三块：

1. **备份**：前置条件（docker volume 路径 / 容器名）、命令、预期产物、校验
2. **恢复**：停止依赖服务、清空数据、导入、重启、验证
3. **参考**：保留策略建议、注意事项（如 Redis perm_epoch 丢失影响）
