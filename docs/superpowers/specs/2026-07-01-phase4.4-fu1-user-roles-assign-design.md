# Phase 4.4-fu1: `PUT /iam/users/:id/roles` 用户角色分配 + 令牌失效接入

> Spec ID: phase4.4-fu1-user-roles-assign
> Status: DRAFT
> Created: 2026-07-01
> Phase: 4.x follow-up
> 前置: Phase 4.4（`iam.permission.changed` + perm-epoch 双写链路已就绪）

## 1. 概述与动机

### 问题

Phase 4.4 已建立「iam 权限变更 → outbox 事件 + Redis perm_epoch 双写 → gateway `iat < perm_epoch` 401」的完整链路，覆盖三条触发路径：

- `role_svc::assign_permissions`（role → permissions 改）
- role 禁用 / 删除
- permission 禁用 / 删除

但 **user → roles** 变更没有写端点。当前 `POST /iam/users` 建用户时按 `req.role_ids` 写 `iam_user_roles`（新建用户尚无 token，不需发事件），此后没有任何 API 能修改已存在用户的角色集合。运维要给某个已登录用户加/减角色，只能直接改 DB，且不会触发令牌失效，用户持旧 token 会继续以旧权限访问。

### 方案

新增 `PUT /iam/users/{user_id}/roles` 端点，**全量替换** 该用户的角色集合。落库同事务发 `iam.permission.changed`（reason=`user_roles_changed`, user_ids=[uid]），commit 后 best-effort 直写 Redis `perm_epoch:{uid}`。完全复用 4.4 已烤熟的 `perm_change::enqueue_permission_changed` + `stamp_perm_epochs` 基建，gateway 与 audit 侧零改动。

### 范围

- 新增写端点 `PUT /iam/users/{user_id}/roles`
- `RoleService::assign_user_roles(user_id, role_ids, actor_id)` 服务方法
- 抽 `set_user_roles_in_tx` 共享 helper，`create_user` 与新端点复用
- `IamError::InvalidRoleIds(Vec<String>)` 新错误变体
- 单测 7 组 + live smoke 验收清单

### 不在本期范围

- 4.4-fu2 actor_id 透传（Principal → service 参数）—— 签名已预留，本期传 `None`
- 4.4-fu3 gateway perm_epoch 本地内存短缓存
- 4.3-fu2 role/dept 接收人解析

## 2. 端点契约

```
PUT /iam/users/{user_id}/roles
Authorization: Bearer <admin_jwt>
Content-Type: application/json

{ "role_ids": ["<role_id_1>", "<role_id_2>", ...] }
```

**响应**：

| Status | Body | 场景 |
|--------|------|------|
| 200 | `{ "user_id": "...", "role_ids": [...] }` | 成功（含 no-op 无变化） |
| 400 | `{ "error": "invalid role_ids", "detail": ["<id>", ...] }` | role_ids 存在未知 / 已禁用 / 已删项，detail 列出具体项 |
| 404 | `"user not found"` | user_id 不存在或已删 |
| 500 | `"internal error"` | DB / 事务失败 |

**语义规则**（决策已 bake）：

- **全量替换**：请求携带的 `role_ids` 集合完全覆盖 `iam_user_roles`。
- **空数组合法**：`role_ids: []` 表示清空该用户所有角色（用户保留、权限收回）。返回 200 + 事件。
- **预检查非法 role_id**：事务内 `SELECT id FROM iam_roles WHERE id IN (...) AND status='active' AND deleted_at IS NULL`。若返回集不等于输入集 → 400 + 未命中项列表。
- **diff-skip**：新旧集合相等（顺序无关、去重后比较）→ 直接返回 200，不 DELETE/INSERT、不发事件、不写 Redis。避免前端表单重复提交、批量幂等重放触发无意义失效。
- **重复输入去重**：`role_ids: ["r1","r1","r2"]` 归一为 {r1, r2}，与 diff-skip 逻辑一致。
- **user_id 校验**：事务内 `SELECT id FROM iam_users WHERE id=? AND deleted_at IS NULL FOR UPDATE`，无 → 404。

**路由挂载**：`services/iam-service/src/routes/roles.rs` 的 `routes()` 追加：

```rust
.route("/iam/users/{user_id}/roles", put(assign_user_roles))
```

URL 属 users 域，handler 落 `RoleService` 使代码与 `assign_permissions` / role 禁删等对称的「变更 → 展开 user_ids → 发事件」路径同族。OpenAPI `tag = "users"` 保持前端 SDK 归属直觉。

**权限守护**：沿用 gateway route table 的 admin 限制（与 `PUT /iam/roles/:id/permissions` 一致），代码层不额外加 `require_role`。不新增权限码。

## 3. 服务层实现

### 3.1 `RoleService::assign_user_roles`

`services/iam-service/src/service/role_svc.rs` 新方法：

```rust
pub async fn assign_user_roles(
    &self,
    user_id: &str,
    role_ids: Vec<String>,
    actor_id: Option<&str>,
) -> Result<Vec<String>, IamError> {
    let mut tx = self.state.db.begin().await?;

    // 1) user 存在性 + 悲观锁（避免并发下 user 被并发删）
    let exists: Option<(String,)> = sqlx::query_as(
        "SELECT id FROM iam_users WHERE id = ? AND deleted_at IS NULL FOR UPDATE"
    ).bind(user_id).fetch_optional(&mut *tx).await?;
    if exists.is_none() { return Err(IamError::UserNotFound); }

    // 2) role_ids 去重 + 预检查
    let dedup: Vec<String> = {
        let s: BTreeSet<String> = role_ids.into_iter().collect();
        s.into_iter().collect()
    };
    if !dedup.is_empty() {
        let placeholders = vec!["?"; dedup.len()].join(",");
        let sql = format!(
            "SELECT id FROM iam_roles WHERE id IN ({}) AND status='active' AND deleted_at IS NULL",
            placeholders
        );
        let mut q = sqlx::query_as::<_, (String,)>(&sql);
        for id in &dedup { q = q.bind(id); }
        let found: Vec<(String,)> = q.fetch_all(&mut *tx).await?;
        let found_set: HashSet<&str> = found.iter().map(|(s,)| s.as_str()).collect();
        let invalid: Vec<String> = dedup.iter()
            .filter(|id| !found_set.contains(id.as_str()))
            .cloned().collect();
        if !invalid.is_empty() { return Err(IamError::InvalidRoleIds(invalid)); }
    }

    // 3) 读旧集合，diff-skip
    let old: Vec<(String,)> = sqlx::query_as(
        "SELECT role_id FROM iam_user_roles WHERE user_id = ?"
    ).bind(user_id).fetch_all(&mut *tx).await?;
    let old_set: BTreeSet<String> = old.into_iter().map(|(r,)| r).collect();
    let new_set: BTreeSet<String> = dedup.iter().cloned().collect();
    if old_set == new_set {
        tx.commit().await?;
        return Ok(new_set.into_iter().collect());
    }

    // 4) 全量替换
    sqlx::query("DELETE FROM iam_user_roles WHERE user_id = ?")
        .bind(user_id).execute(&mut *tx).await?;
    crate::service::user_roles::set_user_roles_in_tx(&mut tx, user_id, &dedup).await?;

    // 5) 同事务 enqueue outbox 事件
    crate::service::perm_change::enqueue_permission_changed(
        &mut *tx,
        self.state.outbox_repo.as_ref(),
        &[user_id.to_string()],
        "user_roles_changed",
        actor_id,
    ).await?;

    tx.commit().await?;

    // 6) commit 后 best-effort 直写 perm_epoch
    crate::service::perm_change::stamp_perm_epochs(&self.state, &[user_id.to_string()]).await;

    Ok(new_set.into_iter().collect())
}
```

**要点**：
- `FOR UPDATE` 锁 user 行，避免并发下 user 被 soft-delete。
- 预检查 + diff 都在事务内（同一 snapshot），避免检查通过后 role 被并发禁用的 TOCTOU。
- 事件同事务写 outbox，DB 与事件原子。
- `stamp_perm_epochs` 在 commit 后 best-effort，失败仅 warn；gateway consumer 会用 set-if-greater 兜底补写（4.4 已有链路）。

### 3.2 共享 helper `service/user_roles.rs`

新模块，供 `create_user` 与 `assign_user_roles` 复用：

```rust
pub(crate) async fn set_user_roles_in_tx(
    tx: &mut sqlx::Transaction<'_, sqlx::MySql>,
    user_id: &str,
    role_ids: &[String],
) -> Result<(), IamError> {
    for role_id in role_ids {
        sqlx::query(
            "INSERT INTO iam_user_roles (user_id, role_id, created_at) VALUES (?, ?, NOW())"
        ).bind(user_id).bind(role_id).execute(&mut **tx).await?;
    }
    Ok(())
}
```

`user_svc::create_user` 现有 loop-INSERT 抽出为对本 helper 的调用：

- 若 `create_user` 当前已用事务：直接替换 loop 为 helper 调用。
- 若 `create_user` 当前非事务：本期同时把它裹入事务（含 user INSERT + role INSERT），避免半完成状态。

### 4.2 Handler

`services/iam-service/src/routes/roles.rs` 追加：

```rust
#[utoipa::path(
    put,
    path = "/iam/users/{user_id}/roles",
    params(("user_id" = String, Path,)),
    request_body = AssignUserRolesRequest,
    responses(
        (status = 200, body = AssignUserRolesResponse),
        (status = 400, description = "invalid role ids"),
        (status = 404, description = "user not found"),
    ),
    security(("bearer_auth" = [])),
    tag = "users"
)]
async fn assign_user_roles(
    State(state): State<AppState>,
    Path(user_id): Path<String>,
    Json(req): Json<AssignUserRolesRequest>,
) -> Result<Json<AssignUserRolesResponse>, (StatusCode, String)> {
    let svc = RoleService::new(state);
    let role_ids = svc.assign_user_roles(&user_id, req.role_ids, None).await.map_err(|e| match e {
        IamError::UserNotFound      => (StatusCode::NOT_FOUND, "user not found".into()),
        IamError::InvalidRoleIds(v) => (
            StatusCode::BAD_REQUEST,
            serde_json::json!({ "error": "invalid role_ids", "detail": v }).to_string(),
        ),
        _ => (StatusCode::INTERNAL_SERVER_ERROR, "internal error".into()),
    })?;
    Ok(Json(AssignUserRolesResponse { user_id, role_ids }))
}
```

## 5. 测试

### 5.1 单测（testcontainers MySQL + Redis）

新增 `services/iam-service/tests/user_roles_assign_test.rs`，7 组：

1. **`assign_user_roles_replaces_and_emits_event`**
   fixture: user u1 + roles r1/r2/r3；u1 初始持 {r1}。
   调 `assign_user_roles("u1", ["r1","r2"], None)`。
   断言：`iam_user_roles` 精确为 {r1, r2}；`iam_outbox_events` 恰新增 1 行 `iam.permission.changed`（payload.user_ids=["u1"], reason="user_roles_changed"）；Redis `perm_epoch:u1` 已写且 TTL > 0。

2. **`assign_user_roles_empty_clears_and_emits`**
   u1 初始 {r1, r2} → 调 `[]` → 落库为空、事件写入、Redis stamp。

3. **`assign_user_roles_no_change_skips_write`**
   u1 初始 {r1, r2} → 调 `["r2","r1"]`（顺序不同）。
   断言：`iam_outbox_events` 无新增行；Redis `perm_epoch:u1` 值未变（先 GET 记录，再断言相等）；返回 200，body.role_ids 精确为 {r1, r2}。

4. **`assign_user_roles_rejects_invalid_role_id`**
   调 `["r1","r_nonexistent"]` → `Err(InvalidRoleIds(vec!["r_nonexistent"]))`。
   断言：DB 未动、无 outbox 行、无 Redis 写。

5. **`assign_user_roles_rejects_disabled_role`**
   r2 status=disabled → 调 `["r1","r2"]` → `InvalidRoleIds(["r2"])`。

6. **`assign_user_roles_user_not_found`**
   user_id="ghost" → `Err(UserNotFound)`。

7. **`assign_user_roles_dedups_input`**
   调 `["r1","r1","r2"]` → 落库 {r1, r2}、outbox 1 行。
