# Phase 4.2: `iam.login.failed` 事件 + 简易风控消费者

> Spec ID: phase4.2-login-failed-risk
> Status: DESIGN APPROVED
> Created: 2026-06-27
> Phase: 4.x 小迭代（每个子任务一个 spec）
> 前置: Phase 4 事件总线（已闭环）、Phase 4.1（notification consumer 模式参考）

## 1. 概述

iam-service 在每一次登录认证失败时，通过既有的事务性 outbox 机制发出新领域事件
`iam.login.failed`。同一个事件喂给 audit-service 的两个关注点：

1. **审计落库（零改动）**：audit-service 现有 consumer 绑定 `iam.#`，`iam.login.failed`
   会自动落入 `audit_events`，无需新增绑定或 handler。
2. **风控计数（新增）**：一个独立 consumer 订阅 `iam.login.failed`，在 Redis 里按
   username / IP 两维度维护滑动窗口计数；窗口越过可配置阈值（默认 5 次 / 5 分钟）时，
   打结构化 WARN 日志 + 递增 Prometheus 计数器。仅「计数 + 告警」。

### 不在本期范围（推迟）

- 账号锁定 / 临时封禁
- 管理员通知（WebSocket / 公告）
- 分布式攻击关联、按失败原因区分阈值
- 风控计数的 event_id 幂等去重（见 §4.3，有意为之）

## 2. 事件契约（`contracts/events.yaml`）

新增第四个事件，紧跟现有三个之后：

```yaml
  iam.login.failed:
    schema_version: 1
    description: "登录失败"
    payload:
      username:   { type: string, required: true }   # 用户输入的用户名（永远已知）
      user_id:    { type: string, required: false }  # 命中真实用户时填，未知用户为空
      ip:         { type: string, required: true }
      user_agent: { type: string, required: false }
      reason:     { type: string, required: true }   # bad_password | user_disabled | password_expired | user_not_found
```

- `scripts/contracts-gen.js` 自动生成 `IamLoginFailed` struct + routing-key 常量
  `iam.login.failed`，并加入 `IamEventEnum`（与 4.x 既有 codegen 流程一致）。
- `reason` 用普通 string，不引入枚举类型，保持 payload 扁平、向后兼容。
- 生成后须跑 `node scripts/contracts-gen.js` 并 `--check` 确认 in-sync。

## 3. iam-service 生产端

### 3.1 当前四条失败路径（`services/iam-service/src/service/auth_svc.rs::login`）

| reason | 当前行为 | user_id |
|--------|---------|---------|
| `user_not_found` | `InvalidCredentials` 直接返回，**无写库** | 无 |
| `user_disabled` | 提前返回，**无写库** | 有 |
| `password_expired` | 提前返回，**无写库** | 有 |
| `bad_password` | 先 `record_login_log(success=false)` 再返回 | 有 |

### 3.2 改动

新增私有方法 `record_login_failure(...)`，把「写失败登录日志 + enqueue 事件」收进
**同一个事务**，四条失败路径全部改为调用它再返回错误：

```rust
async fn record_login_failure(
    &self,
    username: &str,
    user_id: Option<&str>,
    ip: &str,
    user_agent: &str,
    reason: &str,
) -> Result<(), IamError> {
    let mut tx = self.state.db.begin().await?;
    // 1) 失败登录日志（user_id 可空）
    sqlx::query(
        "INSERT INTO iam_login_logs (id, user_id, username, ip_address, user_agent, \
         login_type, success, error_message, created_at) \
         VALUES (?, ?, ?, ?, ?, 'password', false, ?, NOW())",
    )
    .bind(nanoid!())
    .bind(user_id)          // Option<&str> → NULL when None
    .bind(username)
    .bind(ip)
    .bind(user_agent)
    .bind(reason)
    .execute(&mut *tx)
    .await?;
    // 2) 同事务 enqueue iam.login.failed
    let envelope = Envelope::new("iam-service", IamLoginFailed {
        username: username.to_string(),
        user_id: user_id.map(|s| s.to_string()),
        ip: ip.to_string(),
        user_agent: Some(user_agent.to_string()),
        reason: reason.to_string(),
    });
    MySqlOutboxRepo::new(self.state.db.clone())
        .enqueue(&mut tx, &envelope)
        .await
        .map_err(|e| IamError::Internal(e.to_string()))?;
    tx.commit().await?;
    Ok(())
}
```

### 3.3 要点与约束

- **统一所有路径**：`user_disabled` / `password_expired` 现在也写失败日志 + 发事件
  （之前什么都不写），让风控能看到「禁用账号仍被反复尝试」这类信号。
- **`user_not_found` 的外键约束**：`iam_login_logs` 有
  `FOREIGN KEY (user_id) REFERENCES iam_users(id)`。`user_not_found` 路径必须传
  `user_id = None`（绑定为 SQL NULL），**不能**传空字符串，否则违反外键。
  `iam_login_logs.user_id` 已是可空 `VARCHAR(36)`，无需改 schema。
- **取消现有的 `record_login_log(..., false, ...)` 调用**（bad_password 路径），
  由新方法替代，避免双写。`record_login_log` 若不再有其它调用方则一并删除（死方法）。
- **风险（已接受）**：`user_not_found` 会把任意输入用户名落库 + 发事件——这正是探测攻击的
  信号，符合 IP-spray 计数意图；代价是 `iam_login_logs` 会出现垃圾用户名行，可接受。
- 成功路径（含 `iam.login.succeeded` enqueue）不改动。

## 4. audit-service 风控消费端

### 4.1 审计落库（零改动）

`iam.login.failed` 匹配现有 `audit.iam-events` 队列的 `iam.#` 绑定，自动经
`consumer.rs::persist` 落入 `audit_events`（含 event_id 幂等）。不改这条路径。

### 4.2 新增独立风控 consumer

新增模块 `services/audit-service/src/risk.rs`，独立 consumer：

```
队列:  audit.login-risk
绑定:  iam.login.failed          (仅此一个 routing-key)
DLX:   events.dlx                (与现有队列同款 x-dead-letter-exchange)
```

独立队列而非搭车 `persist` 的理由：审计落库（全部 iam.# 持久化）与风控（仅 login.failed
计数）两个关注点解耦，各自独立 ack/nack/DLQ；风控 handler 失败（如 Redis 抖动）不应
阻塞或 nack 审计落库。

`run()` 套用现有 `consumer.rs` 的 5s 重连回退循环模式。

### 4.3 滑动窗口逻辑

每条 `iam.login.failed`，对 user 维度（`payload.username` 非空时）与 ip 维度各做一次：

```
key = "audit:loginfail:user:{username}"   或   "audit:loginfail:ip:{ip}"
n   = INCR key
if n == 1:          EXPIRE key {window_secs}     # 首次出现才设过期 → 滑动窗口
if n == threshold:                                # 恰好越线时只告警一次
    warn!(dimension, key_value, count = n, window_secs,
          "login failure threshold exceeded");
    LOGIN_RISK_ALERTS.with_label_values(&[dimension]).inc();
```

- `n == threshold`（用「等于」而非「≥」）保证一个窗口内只告警一次，不刷屏。
- **Redis 出错时照常 ack**：`warn!` 记录后吞掉错误返回 `Ok`。风控是尽力而为，不能因
  Redis 抖动把消息卡进 DLQ。
- **不做 event_id 幂等去重**（有意为之）：RabbitMQ 至少一次投递下偶发重投会让计数略偏高，
  对「越线告警」近似信号可接受，且强行幂等需额外存储。
- 复用 notification-service `redis_cli` 模式，给 audit-service 新建轻量 Redis 封装
  （只需 INCR + EXPIRE）。

## 5. 配置、Schema、接线、可观测性

### 5.1 audit-service 配置（`config.rs`，新增字段，沿用 `from_env` 风格）

| 变量 | 默认 | 说明 |
|------|------|------|
| `REDIS_URL` | `redis://127.0.0.1:6379` | 风控窗口存储 |
| `EVENT_BUS_URL` | 复用现有默认 | 已有（consumer 用） |
| `LOGIN_RISK_THRESHOLD` | `5` | 窗口内失败次数阈值 |
| `LOGIN_RISK_WINDOW_SECS` | `300` | 滑动窗口秒数 |

### 5.2 schema 确认

- `iam_login_logs.user_id`：已可空 `VARCHAR(36)`，**无 schema 改动**。
- 无新表（风控只用 Redis；审计落库复用既有 `audit_events`）。

### 5.3 main.rs 接线

audit-service `main.rs` 在已有 `consumer::run(...)` spawn 之外，再
`tokio::spawn(risk::run(redis, event_bus_url, opts))`，同样带 5s 重连回退。

### 5.4 Prometheus

新增 counter `login_risk_alerts_total{dimension="user|ip"}`，越线时 inc，
通过现有 `/metrics` 端点暴露。

### 5.5 基础设施

- `infrastructure/.../definitions.json`：预声明 `audit.login-risk` 队列 +
  `iam.login.failed` 绑定 + `x-dead-letter-exchange: events.dlx`。
- `docker-compose-infra.yml`：给 audit-service 注入 `REDIS_URL`（Redis 容器已存在）。
