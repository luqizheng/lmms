## 1. 概述与动机

### 问题

`ensure_welcome_for_user`（`services/notification-service/src/service/announcement_service.rs:52`）
在事务提交后用 `WsHub::publish` 进程内直推。`WsHub` 是 `Arc<RwLock<HashMap<user_id, broadcast::Sender>>>`，
**每个副本独立**。多副本部署下：
- iam.user.created 经 durable queue 负载均衡到副本 A
- 该副本欢迎入库 + 在自己的 hub 上 publish
- 用户 WS 实际连在副本 B → B 的 hub 不知道这条消息 → live 推送丢失

Hub 注释（`ws_hub.rs:1` 周围）已明说这是"进程内"。

### 方案

复用 4.3 已有的事件驱动路径：`ensure_welcome_for_user` 不再调 `hub.publish`，
改为同事务 outbox enqueue 一条 `notification.announcement.published` 事件（与
`Db::publish_announcement` 完全一致的事件 payload、同一张 `ntf_outbox_events`）。
事件经 `ntf-outbox-publisher` 发到 RabbitMQ `events` exchange，每个 notification-service
副本的 ephemeral 队列拿到一份，由 `announcement_events::handle` 推到本地 hub——
只有那个连着 WS 的副本真正到达用户。

**reload 兜底语义保留**：delivery 行已落库（announcement_service.rs:127 行的
`INSERT IGNORE ntf_announcement_deliveries`），WS 推送本来就是 best-effort，
漏推由 `list_for_user` reload 补齐。本改动不引入新的兜底机制。

### 范围

仅 `ensure_welcome_for_user` 内的 WS 推送入口。

### 不在本期范围

- `publish_announcement` 已走事件驱动，本次不动（参照 4.3 spec）。
- 推送 metrics / 幂等去重 / role/dept 解析：均与 4.3 同状态（existing follow-up）。
- 删 `WsHub`：仍要消费侧用，不删。

## 2. 数据流

```
iam.user.created (RabbitMQ)
   │
   ▼  durable queue "notification.iam-events"  load-balanced
notification-service [任一副本]
   │
   ▼  consumer/iam_events::handle_iam_user_created
announcement_service::ensure_welcome_for_user (本改动)
   │
   │  tx {
   │    INSERT ntf_event_idempotency        ← 已存在
   │    INSERT ntf_announcements            ← 已存在
   │    INSERT ntf_announcement_recipients  ← 已存在
   │    INSERT IGNORE ntf_announcement_deliveries  ← 已存在
   │    MySqlOutboxRepo::enqueue(
   │        Envelope<NotificationAnnouncementPublished>{
   │            user_ids: json!([user_id])
   │        })                              ← NEW
   │  } commit
   │  redis.incr_unread(user_id, 1)         ← 非事务，与现状一致
   ▼
ntf-outbox-publisher（sidecar）
   │  publish to events exchange, routing-key notification.announcement.published
   ▼
所有 notification-service 副本 [每副本一条 ephemeral queue, fanout]
   │
   ▼  announcement_events::handle
   │  for uid in user_ids: hub.publish(uid, WsOut::New{...})
   │  ← 仅连接本副本 WS 的 uid 真正送达；其它副本 noop
```

## 3. 改动清单

### 3.1 `services/notification-service/src/service/announcement_service.rs`

**`ensure_welcome_for_user` 签名变更**：

- 移除参数 `hub: &WsHub`（无外部调用方仍持有强引用即可，因为是 `&` 借用）
- 新增参数 `outbox_repo: &MySqlOutboxRepo`（与 db.rs:340 self.outbox_repo 同形）

**函数体变更**：

- 去掉末尾 `hub.publish(user_id, WsOut::New{...})` 块（lines 140–149）
- 在 `tx.commit()` 之前（同 `publish_announcement` 末尾），调用：
  ```rust
  let mut envelope = Envelope::new(
      "notification-service",
      NotificationAnnouncementPublished {
          announcement_id: ann_id as i64,
          title,
          pinned: false,
          popover: false,
          user_ids: serde_json::json!([user_id]),
      },
  );
  outbox_repo
      .clone()
      .enqueue(&mut tx, &mut envelope)
      .await
      .map_err(|e| anyhow::anyhow!("outbox enqueue: {e}"))?;
  ```

要点：
- **outbox enqueue 必须在事务内**：与现有 4.3 / 5B-fu3 模式一致。若 enqueue 失败 → tx 回滚
  → 上游 handler 抛 Transient → broker 重投；同 event_id 的重投被 idempotency 行挡住，
  不会重复 enqueue（key=event_id 行已存在的 INSERT 即 0 rows affected）。
- `pinned=false, popover=false`：与原 hub.publish JSON 字面量一致（`announcement_service.rs:142–148`）。
- `user_ids` 用 `serde_json::json!([user_id])`：与 `announcement_events::handle`
  `serde_json::from_value::<Vec<String>>` 期望一致。
- `incr_unread` 留在 `tx.commit()` 之后：非事务、best-effort、warn-on-error（与现状一致）。
  Redis 抖动不应阻塞事件投递。

**imports**：去掉 `use crate::ws_hub::{WsHub, WsOut};`。
新增 `use common_event::{Envelope, MySqlOutboxRepo};` 和 `use common_event::events::NotificationAnnouncementPublished;`。

### 3.2 `services/notification-service/src/consumer/iam_events.rs`

`handle_iam_user_created` 签名：
- 去掉 `hub: &WsHub` 参数
- 新增 `outbox_repo: &MySqlOutboxRepo` 参数
- 转发给 `ensure_welcome_for_user`

`WsHub` 的 import 同步删除。

### 3.3 `services/notification-service/src/consumer/mod.rs`

`run`、`try_subscribe`：增加 `outbox_repo: Arc<MySqlOutboxRepo>` 参数；闭包内 clone 给 handler。

### 3.4 `services/notification-service/src/main.rs`

`consumer::run` 调用点：传入 `db.outbox_repo.clone()`（`db.outbox_repo` 已是 `Arc<MySqlOutboxRepo>`，与 iam `MySqlOutboxRepo::new(state.outbox_repo.as_ref())` 路数对齐 — 这里是 root 持有，cloned for each spawn）。

### 3.5 `services/notification-service/tests/welcome_consumer_test.rs`

`welcome_idempotent_and_renders_template`：把 `let hub = WsHub::new();` 与
两处 `&hub` 替换为 `db.outbox_repo.as_ref()`；保持现有断言覆盖（idempotent + template 渲染）。
**新增第二个 `#[ignore]` 集成测**（可选，但对应 §5 测试战略的 *G outbox 行写入*）：
- 调用一次 → `SELECT COUNT(*) FROM ntf_outbox_events WHERE routing_key='notification.announcement.published'` 严格 == 1；
- 再次同 event_id → 不新增。

## 4. 错误处理

| 失败点 | 行为 | 来源 |
|---|---|---|
| outbox enqueue 失败 | anyhow err 抛出 → 上游 handler 返 `HandlerError::Transient` → broker 重投 → bounded 3 次后 DLQ | 与 4.3 一致 |
| `redis.incr_unread` 失败 | warn 日志，不影响事件投递（best-effort） | 现状，保留 |
| idempotency 行命中 | tx commit 后返 `Ok(false)`，**不**写 outbox 行 | 现状，保留 |
