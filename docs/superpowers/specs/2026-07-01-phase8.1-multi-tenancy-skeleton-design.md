# Phase 8.1 — 多租户骨架（Skeleton）

> 日期：2026-07-01
> 来源：`TODO.md` Phase 8「多租户基础」全量重写。
> 范围：仅交付**骨架层** —— Tenant 实体、JWT claim、注册接口、`TenantScope` extractor、
> `digua_common-db` helper、event envelope 接入、default tenant 兜底。
>
> **不在本期范围**：业务表 schema 加列与迁移（→ Phase 8.2）、查询点全量改造与跨租户黑名单 e2e（→ Phase 8.3）。
>
> **已锁定的设计决策**（brainstorm 2026-07-01，所有问题取推荐方案）：
> - D1 共享 MySQL `superpowers` 库 + 业务表加 `tenant_id` 列
> - D2 一用户 = 一租户（`iam_users.tenant_id` 不可变）
> - D3 自助注册 `POST /iam/tenants` + 同事务建 admin + 发 `iam.tenant.created`
> - D4 JWT claim `tid` 为唯一来源（不信任 Header / URL）
> - D5 `tenant_id` 类型 `BIGINT UNSIGNED` 自增
> - D6 permissions 全局 / roles 租户独有
> - D7 拆 3 个子 spec：8.1 骨架 / 8.2 表迁移 / 8.3 贯通

---

## 1. 背景与问题

当前项目**完全没有多租户概念**：

- `libs/jwt-ctx::Principal`（`principal.rs:8`）只有 `user_id / user_code / dept_id / roles / permissions`，无 `tenant_id`。
- `iam-service` 的 JWT 签发（`token_svc.rs:40 issue_access_token`）只塞 `sub / roles / permissions`。
- 所有业务表共用 MySQL `superpowers` 库且无 `tenant_id` 列，user 注册即默认全局可见。
- `libs/digua_common-event::Envelope`（`envelope.rs:17`）虽然预留 `tenant_id: Option<String>`，但 producer 从未填充（与 trace_id 同类问题）。
- 没有任何 `TenantScopedQuery` / `TenantScope` extractor。

后果：项目无法对外作为 SaaS 形态运行 —— 两家公司用同一套，看到对方的全部用户、公告、文件、操作日志。

## 2. 目标 / 非目标

### 目标（本期交付）

1. **Tenant 实体落库**：`iam_tenants` 表 + `iam_users.tenant_id` 外键列（仅这一张业务表加，作为穿透样板）。
2. **JWT 携带 tenant_id**：签发时塞 `tid` claim；`Principal` 暴露 `tenant_id: i64` 必填字段。
3. **自助注册接口**：`POST /iam/tenants`，同事务建 tenant + admin user + 默认 `tenant_admin` role；发 `iam.tenant.created` 事件。
4. **`TenantScope` extractor**：Axum extractor，从 `Principal` 直接派生，handler 显式声明。
5. **`digua_common-db` helper**：`scope_tenant(query_builder, &TenantScope)` 工具函数，自动追加 `WHERE tenant_id = ?` 子句 + 索引提示。
6. **Event envelope 接入**：`Envelope::with_tenant_from_principal(&p)` 一行注入；audit consumer 把 tenant_id 落 `audit_*` 表（仅扩 schema，不强校验，留 8.2 完成）。
7. **default tenant 兜底**：dev / migrate 数据走 `tenant_id = 1`（`default`），保证 8.1 上线后存量 e2e 不挂。

### 非目标

- 业务表（roles / permissions / announcements / audit_* / ntf_* / cfg_* / file_* / prue_*）schema 加 `tenant_id` 列 —— Phase 8.2。
- 所有 `sqlx::query` 改写注入 tenant_id 过滤 —— Phase 8.2 / 8.3。
- 跨租户访问黑名单 e2e、roles 改造为租户独有、gateway 跨租户检测 —— Phase 8.3。
- tenant 计费、quota、生命周期管理（暂停 / 删除 / 数据导出）—— 产品形态明确后再开 Phase。
- platform-admin 后台跨租户视图 —— 不在 SaaS 自助注册 MVP 范围。

## 3. 设计

### 3.1 Tenant 实体

新表 `iam_tenants`：

```sql
CREATE TABLE IF NOT EXISTS iam_tenants (
    id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
    slug         VARCHAR(64)     NOT NULL,
    display_name VARCHAR(128)    NOT NULL,
    status       VARCHAR(16)     NOT NULL DEFAULT 'active',  -- active | suspended
    created_at   DATETIME        NOT NULL,
    updated_at   DATETIME        NOT NULL,
    UNIQUE KEY uk_tenant_slug (slug)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

INSERT INTO iam_tenants (id, slug, display_name, status, created_at, updated_at)
VALUES (1, 'default', 'Default Tenant', 'active', NOW(), NOW())
ON DUPLICATE KEY UPDATE id = id;
```

- `slug` 是人类可读 ID（URL 不暴露，仅用于运维识别 / 登录页区分），`id` 才是穿透业务的真锚点。
- 不删 tenant，仅 `status='suspended'`（数据保留 + 拒绝登录）。
- `id=1` 保留给 `default`，由迁移种子写入，**所有 8.2 之前的存量数据 backfill 到 tenant 1**。

`iam_users` 加列（本期就改这一张）：

```sql
ALTER TABLE iam_users
    ADD COLUMN tenant_id BIGINT UNSIGNED NOT NULL DEFAULT 1 AFTER id,
    ADD CONSTRAINT fk_iam_users_tenant FOREIGN KEY (tenant_id) REFERENCES iam_tenants(id),
    DROP INDEX username,                                       -- V001 匿名 UNIQUE，MySQL 默认索引名 = 列名
    ADD UNIQUE KEY uk_tenant_username (tenant_id, username);
```

注意点：
- **username 唯一性从全局降级为 tenant 内** —— 两家公司可以都有 `admin`。spec §6 风险节会重点 review。
- 已有用户 backfill `tenant_id=1`（DEFAULT 1 包办，无需手写 UPDATE）。
- 索引：`(tenant_id, username)` 复合 unique 覆盖 login 的 username lookup；删旧 `uk_username`。

### 3.2 JWT claim 升级

`services/iam-service/src/service/token_svc.rs::issue_access_token` 签名扩展（iam 自带 JWT 签发，不调用独立 token-service）：

```rust
pub fn issue_access_token(
    &self,
    user_id: &str,
    username: &str,
    tenant_id: i64,         // 新增
    roles: Vec<String>,
    permissions: Vec<String>,
) -> Result<String, IamError>
```

签发时塞 `claims.custom["tid"] = tenant_id`（数字，不是字符串 —— 减少前端误用 / 减少 token 体积几个字节）。

JWT payload 示例：
```json
{
  "sub": "u_abc",
  "user_code": "alice",
  "tid": 7,
  "roles": ["tenant_admin"],
  "permissions": ["iam.user.read", ...],
  "iat": 1735689600,
  "exp": 1735776000
}
```

兼容期：**无 `tid` claim 的旧 token 视为 `tenant_id=1`**（default tenant）。Phase 8.3 收紧为硬拒（401）。

### 3.3 Principal 扩展

`libs/jwt-ctx/src/principal.rs`：

```rust
pub struct Principal {
    pub user_id: String,
    pub user_code: String,
    pub tenant_id: i64,      // 新增，必填，缺失 default=1
    pub dept_id: Option<i64>,
    pub roles: Vec<String>,
    pub permissions: HashSet<String>,
}
```

解析逻辑：
```rust
let tenant_id = payload.get("tid").and_then(|v| v.as_i64()).unwrap_or(1);
```

`unwrap_or(1)` 是过渡期，与 §3.2 兼容期保持一致；Phase 8.3 改 `ok_or(PrincipalError::MissingTenantId)`。

### 3.4 `TenantScope` extractor

新增 `libs/jwt-ctx/src/scope.rs`：

```rust
#[derive(Debug, Clone, Copy)]
pub struct TenantScope(pub i64);

impl<S: Send + Sync> FromRequestParts<S> for TenantScope {
    type Rejection = StatusCode;
    async fn from_request_parts(parts: &mut Parts, state: &S) -> Result<Self, Self::Rejection> {
        let p = Principal::from_request_parts(parts, state).await?;
        Ok(TenantScope(p.tenant_id))
    }
}
```

**为什么显式 `TenantScope` 而非直接 `principal.tenant_id`？**
- handler 签名里出现 `scope: TenantScope` = "本 handler 已做租户隔离"，code review 一眼可见。
- 后续如果要加 `cross_tenant: bool`（platform-admin 越权），改 extractor 一处即可。
- 编译期保证：handler 没写 `TenantScope` 又想用 `scope_tenant!` 会编译失败。

### 3.5 `digua_common-db` scope helper

新增 `libs/digua_common-db/src/scope.rs`：

```rust
use sqlx::{query_builder::QueryBuilder, Database};
use digua_jwt_ctx::TenantScope;

pub trait WithTenantScope<'a, DB: Database> {
    fn and_tenant(self, scope: &TenantScope) -> Self;
}

impl<'a, DB: Database> WithTenantScope<'a, DB> for QueryBuilder<'a, DB>
where i64: sqlx::Encode<'a, DB> + sqlx::Type<DB>,
{
    fn and_tenant(mut self, scope: &TenantScope) -> Self {
        self.push(" AND tenant_id = ").push_bind(scope.0);
        self
    }
}
```

业务侧用法：
```rust
let mut qb = QueryBuilder::new("SELECT id, username FROM iam_users WHERE deleted_at IS NULL");
qb.and_tenant(&scope);
let users = qb.build_query_as::<User>().fetch_all(&pool).await?;
```

**注意**：本期只提供 helper、只接 iam-service `iam_users` 一张表作为示范；其他业务点改造在 8.2 跟随表迁移做。

漏注入怎么发现？
- code review（核心防线）—— handler 拿了 `TenantScope` 但 SQL 里没出现 tenant_id = ⚠️
- 8.3 落一个 `scripts/check-tenant-scope.js`：扫所有 `.rs` 文件，对带 `TenantScope` 参数的函数检查同函数内 SQL 是否包含 `tenant_id`（启发式 grep，不保证 100%，但拦得住大部分）。

### 3.6 Event envelope 接入

`libs/digua_common-event/src/envelope.rs::Envelope` 已有 `tenant_id: Option<String>` + `with_tenant_id(impl Into<String>)` 构造器，本期不动 lib。

producer 5 处 callsite（iam-service 那 5 个 `Envelope::new` 点，与 trace_id 注入复用）改成链式：
```rust
let envelope = Envelope::new("iam-service", payload)
    .with_tenant_id(principal.tenant_id.to_string());
```

不在 `digua_common-event` 加 `with_tenant_from_principal(&Principal)` 便捷方法：那会让 `digua_common-event` 反向依赖 `jwt-ctx`（基础 lib 依赖 axum extractor lib），收益（少一行代码）抵不上污染。

**字段类型不一致说明**：本期 Principal.tenant_id 是 `i64`，envelope.tenant_id 是 `Option<String>`。producer 永远 `to_string()` 写入，consumer 永远 `parse::<i64>().unwrap_or(1)` 读出。理由：envelope 字段类型已经在生产被序列化（虽然现有数据都是 None），改 schema = 强迫所有现有 outbox / archive / DLQ 待消费消息漂移。

### 3.7 自助注册接口

`POST /iam/tenants`（公开，不要 auth）：

请求：
```json
{
  "tenant_slug": "acme",
  "display_name": "Acme Corp",
  "admin_username": "admin",
  "admin_password": "...",
  "admin_email": "admin@acme.com"
}
```

响应 `201 Created`：
```json
{
  "tenant_id": 7,
  "admin_user_id": "u_xxx"
}
```

事务流程：
```
BEGIN
  INSERT iam_tenants (slug, display_name, status='active') → tenant_id
  INSERT iam_users (tenant_id, username='admin', password_hash=...) → admin_user_id
  INSERT iam_user_roles (user_id, role_id=<全局 'tenant_admin' role>)
  -- 同事务写 outbox
  INSERT iam_outbox_events (envelope) where event = 'iam.tenant.created'
COMMIT
```

> 注：本期 `iam_roles` 表 schema 不动，复用**全局** `tenant_admin` role（由 V003 迁移种子写入：`INSERT iam_roles (id, code, name) VALUES (..., 'tenant_admin', '租户管理员')`）。
> 临时折中：所有租户的 admin 共享同一个 role_id，role 内权限由 `iam_role_permissions` 全局映射。
> 8.2 给 iam_roles 加 tenant_id 列后，注册流程改为"复制全局 tenant_admin 模板到 tenant 内 role"。本期不为这个折中加 e2e 防回归（明显代码痕迹 + 8.2 必动）。

事件：`iam.tenant.created` 加入 `contracts/events.yaml`，payload `{ tenant_id, slug, display_name, admin_user_id }`。

错误处理：
- slug 冲突 → `409 Conflict`（unique 索引）
- admin_username 是 tenant 内 unique，新 tenant 必然成功（不会冲突）
- 整体失败 → 事务回滚，tenant 不留半成品

**速率限制**：注册接口加 IP-based rate limit（沿用现有 `digua_common-ratelimit`，10 次/小时/IP）防滥注。

### 3.8 default tenant 兜底

- 迁移种子保证 `iam_tenants id=1 slug='default'` 一定存在。
- `iam_users.tenant_id DEFAULT 1`：8.2 之前的所有用户自动属于 default tenant。
- 旧 JWT（无 `tid`）→ Principal `tenant_id=1`。
- 旧 envelope（`tenant_id=None`）→ consumer 视为 `tenant_id=1`。

**好处**：8.1 上线不破坏任何现有 e2e；8.2 / 8.3 增量切。
**风险**：default tenant 长期存在会被习惯性当作"管理员后门"。8.3 起 platform-admin 改走单独的 `cross_tenant` flag，default tenant 降级为"未迁移数据隔离区"。

## 4. 数据流

注册：
```
client → POST /iam/tenants
  iam-service:
    BEGIN
      INSERT iam_tenants(slug='acme') → tid=7
      INSERT iam_users(tenant_id=7, username='admin') → uid
      INSERT iam_roles(...) + iam_user_roles
      INSERT iam_outbox_events(envelope{event:'iam.tenant.created', tenant_id:'7'})
    COMMIT
  outbox-publisher → RabbitMQ → audit consumer (落 tenant 创建日志, schema 8.2 才加列, 暂落 default)
  ← 201 { tenant_id: 7, admin_user_id }
```

登录：
```
client → POST /iam/auth/login {username:'admin', password:..., tenant_slug:'acme'}
  iam-service:
    SELECT id FROM iam_tenants WHERE slug='acme' → tid=7
    SELECT * FROM iam_users WHERE tenant_id=7 AND username='admin'
    verify password
    token_svc.issue_access_token(uid, 'admin', tenant_id=7, roles, perms)
    返回 { access_token, refresh_token }
```

下游服务接请求：
```
gateway → service: Authorization: Bearer <jwt with tid:7>
  service handler(scope: TenantScope): ← Principal 解出 tid=7
    QueryBuilder::new("SELECT ... FROM iam_users WHERE ...").and_tenant(&scope)
```

## 6. 风险

| 风险 | 严重度 | 缓解 |
|------|-------|------|
| `iam_users` username 唯一性从全局降级到 tenant 内 → 旧测试可能写死 `admin` 全局唯一 | 中 | 8.1 PR 跑全量 e2e；找到的写死处统一改为 `(tenant_slug, username)` 元组 |
| Envelope.tenant_id 用 String 与 BIGINT 不一致 → consumer 解析失败 | 低 | producer 总 `to_string()`、consumer 总 `parse::<i64>().unwrap_or(1)`；现有 outbox 字段类型不动避免 schema 漂移 |
| 注册接口被滥注 | 中 | IP rate limit + 8.3 加 CAPTCHA / email 验证（本期不做）|
| default tenant 长期被当"全局管理员后门" | 中 | 8.3 platform-admin 改走 `cross_tenant` flag；default tenant 降级为历史数据区 |
| 旧 token 无 `tid` 仍能登录 | 低 | 兼容期；Phase 8.3 收紧为 401 |
| 8.2 / 8.3 未完成时 roles / audit / announcements 仍跨租户可见 | 高 | spec 已声明属于 8.2 / 8.3 范围；test-case/81 文档显式提示"本期只验证 iam_users 隔离" |
| `WithTenantScope` helper 漏用（handler 拿了 scope 但 SQL 没拼）| 高 | 8.3 加 `scripts/check-tenant-scope.js` 启发式扫描；core review 时盯 SQL string |
