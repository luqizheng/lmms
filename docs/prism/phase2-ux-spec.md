## 1. 全局导航架构结论

| 场景 | 结论 | 理由 |
|---|---|---|
| 展示页（设计系统官网） | **单页锚点导航 + 原生锚点滚动**，不做路由分页 | 内容总量 7 章、一次讲完的叙事型页面；锚点保证分享链接直达任一章；无路由切换成本，`prefers-reduced-motion` 降级只影响过渡不影响结构 |
| Dashboard 概念页 | **与展示页同站、路由分页**（`/` 展示页 → `/dashboard` 概念页，整页路由跳转） | 概念页承载完整模拟数据与交互（搜索、筛选、排序），混入锚点流会破坏展示页叙事节奏 |
| 互通入口 | 展示页 Hero「进入 Dashboard」→ `/dashboard`；Dashboard 左下角 Logo → `/` | 保证两页互相可达、可回退 |

**展示页锚点导航实现细节：**
- Header 常驻 4 个锚点：`#principles`（设计理念）/ `#foundation`（设计基础）/ `#components`（组件）/ `#dashboard`（概念预览）。次要章节（Hero / 落款）不占导航位，避免 640px 断点换行。
- 锚点定位补偿：吸顶 Header 高 64px，锚点目标 `scroll-margin-top: 80px`（64 + 16 缓冲，唯一值）。
- 当前章节高亮：IntersectionObserver `rootMargin: -40% 0 -55% 0`（触发线约在视口 40%–45% 区间）切换 Header 当前项指示条。

### 2.2 顺序理由

1. **Hero → 理念 → 基础（色彩/字体/间距）→ 组件 → 实战 → 收束**，是从「气质 → 原则 → 原子 → 分子 → 场景」的漏斗，与用户评估一套设计系统的决策顺序一致（先信气质，再查标尺，最后看落地）。
2. 色彩先于字体：浅色系统第一争议点永远是「白底上的灰阶层次与文字对比是否发飘」，用对比度表先自证。
3. 组件章放在基础三章之后：组件是 token 的应用结果，先有标尺后有实例，避免读者倒查。
4. Dashboard 预览压轴但在落款之前：它是全页叙事的高潮与转化点（导流 `/dashboard`），落款只做安静收尾。

### 2.3 每章统一骨架

| 元素 | 规格（全部引用 Phase 1R） |
|---|---|
| 章节容器 | `max-width: 1280px`，左右 padding ≥32px（1024 起），章间 `--space-16`（64px） |
| 章节标题 | H2（28px/600）+ 章节序号（mono caption，tertiary），下方 `--space-6` 进内容 |
| 章节导语 | body 15px · secondary · 最多 2 行 · 与首内容块间距 `--space-8` |

## 4. 响应式策略（五断点唯一结论）

断点：`640 / 768 / 1024 / 1280 / 1600`（min-width，移动优先）。每行给出该断点的**起效布局**。

### 4.1 展示页

| 断点 | 布局结论 |
|---|---|
| <640（基准） | 单列：所有章节内容 1 列满宽（左右 padding 20px）；Hero 数字墙 2×3 网格；理念卡 1 列；组件实例区纵向堆叠（标签在上、实例在下）；Header 导航折叠为汉堡菜单（菜单展开为 E2 下拉面板，含 4 锚点 + 「进入 Dashboard」按钮） |
| ≥640 | 章节容器左右 padding 24px；Hero 数字墙 4×2；理念卡 2 列；组件实例维持纵向堆叠 |
| ≥768 | 理念卡 2 列不变；色彩/字体/间距章的演示矩阵允许 2 列；Header 直接显示 4 锚点（收起汉堡） |
| ≥1024 | 12 栏栅格生效：章节标题占左 3 栏（sticky）、内容占右 9 栏的「规范文档式」双栏；组件实例改为「标签在左、实例在右」横排 |
| ≥1280 | 容器封顶 1280px 居中；双栏结构不变 |
| ≥1600 | 仅背景延展，容器维持 1280px（展示页不用 1600 容器，内容密度不需要） |

### 4.2 Dashboard

| 断点 | 布局结论 |
|---|---|
| <640（基准） | **侧边栏彻底隐藏**，改由顶栏最左汉堡按钮唤出（抽屉：白底 240px 宽 + shadow-md，从左滑入 240ms decelerate，遮罩 `rgba(23,24,28,0.28)` 暖黑纱——浅色遮罩压灰不压黑，Esc/点遮罩关闭并还焦给汉堡）；指标卡 1 列；图表区纵向堆叠（面积图在上、进度环卡在下）；**表格卡片化**（行变卡：每行渲染为一张 raised 卡，字段名 small tertiary + 字段值，状态 Badge 保留，卡间距 `--space-3`）；顶栏搜索框收为 36×36 图标按钮（`search`），点击全屏展开 |
| ≥640 | 指标卡 2×2；表格**恢复为表格 + 横向滚动**（唯一交叉点：<640 卡片化，≥640 横滚，不做两方案并存）；横向滚动容器右缘渐隐提示（`mask-image` 线性渐变），首列（服务名）不粘滞——数据列少，粘滞无必要 |
| ≥768 | **侧边栏以收起态（64px）常驻**（仅图标，hover/聚焦显示 tooltip 浮层含菜单名，E2 规格）；顶栏左角新增「展开侧边栏」图标按钮（`panel-left`）；指标卡维持 2×2；图表区维持纵向堆叠 |
| ≥1024 | **侧边栏完整展开（240px）**，展开/收起由用户控制且状态存 localStorage；指标卡 4×1；图表区恢复左 2/3 + 右 1/3 双栏 |
| ≥1280 | 主内容区 `max-width` 解除，图表双栏比例不变，表格列距随 `--space-4` 自然增密 |
| ≥1600 | 容器封顶 1600px（Phase 1R §4.1 允许），指标卡 4×1 不变，图表高度维持 320px，多出宽度给表格列呼吸 |

**降级链一句话**：侧边栏 隐藏→图标→完整（640 / 768 / 1024 三档触发）；指标卡 1→2→4 列（640 / 1024）；表格 卡片化→横滚→自然表格（640 / 768）。**表格在窄屏的结论是「<640 卡片化、≥640 横向滚动」，无第二方案。**

## 5. 无障碍规范

### 5.1 键盘遍历顺序（Tab 顺序原则）

1. **DOM 顺序即 Tab 顺序**：禁止用 `tabindex > 0` 重排；自定义组件一律 `tabindex="0"`（容器）或 `-1`（编程聚焦的子项）。
2. **视觉顺序 = DOM 顺序**：布局不得让视觉与 DOM 脱节（展示页双栏 sticky 标题随内容流，Dashboard 顶栏 → 指标卡 → 图表 → 表格 → 分页器自上而下）。
3. **Dashboard 全局快捷键**：`⌘K / Ctrl+K` 唤起搜索；`Esc` 关闭最上层浮层（还焦给触发器）；`/` 聚焦搜索（当焦点不在输入框时）。快捷键用 `<kbd>` 样式呈现，且在 screen reader 文案中念出。
4. **跳过链接**：两页均提供「跳到主内容」（`skip-link`，聚焦时可见：raised 白底 + accent 描边，Tab 首站）。
5. **图标按钮必须可聚焦**且带可访问名；纯装饰图标 `aria-hidden="true"` 不入 Tab。
6. **浅色新增**：ink 墨色页脚/CTA 面板上链接与文字一律 `--text-inverse`，焦点环同全局（钴蓝对墨底 3:1 达标，可加 2px 白外衬强化）；disabled 文案（2.7:1 低于 4.5）**必须**同时叠 `--surface-hover-veil` 底或去除交互语义，不得裸灰字表达禁用。

### 5.2 焦点管理

| 场景 | 规则 |
|---|---|
| 焦点环 | 承 Phase 1R：`:focus-visible` 才显示，`outline: 2px solid accent; offset 2px` + 4px `rgba(46,91,255,0.18)` 光晕（浅色下光晕 alpha 由 25% 降至 18%，防白底发脏），150ms 显隐 |
| Modal | **焦点陷阱**：打开后焦点移入第一个可聚焦元素（无则移到 Modal 容器）；Tab 在 Modal 内循环（最后元素 → 第一个，Shift+Tab 反向）；Esc 关闭；关闭后**焦点还给触发器**。进出动画 320ms（Phase 1R 上限），动画结束才转移焦点 |
| 下拉（Select / 菜单） | 打开后**首项预高亮**（视觉高亮 + `aria-activedescendant` 指向首项，键盘上下移动、Enter 选中、Esc 关闭还焦）；类型-ahead 支持拼音首字母不做硬性要求，字母匹配即可 |
| 命令面板（顶栏搜索） | 同 Modal 焦点陷阱；输入即过滤；上下选择 + Enter 跳转；Esc 还焦搜索框 |
| 抽屉（<640 侧边栏） | 同 Modal：开即聚焦第一个菜单项，陷阱内循环，关闭还焦汉堡按钮 |
| Toast | **不抢焦点**；`role="status"`（info/success）或 `role="alert"`（warning/danger）自动播报 |
| 路由切换 | `/` ↔ `/dashboard` 切换后焦点移至 `<main>` 顶部（`tabindex="-1"` 编程聚焦），并向 screen reader 播报页面标题（`aria-live` 礼貌区） |

### 5.3 屏幕阅读器要点

| 对象 | 处理 |
|---|---|
| 语义地标 | 每页固定五件套：`<header>`（banner）/ `<nav>` / `<main>` / `<aside>`（Dashboard 侧边栏）/ `<footer>`（contentinfo），均有 `aria-label`（如 nav: 「章节导航」） |
| 页面标题 | `document.title` 随路由切换（「PRISM — 明亮 SaaS 设计系统」/「概览 · PRISM Dashboard」） |
| 图表文本替代 | 面积图：`role="img"` + `aria-label` 一句话摘要（「过去 7 天请求趋势：从 12.4 万增长至 18.9 万，峰值 21.3 万」），并在图表下方提供**视觉可见的数据摘要行**（small · tertiary，全用户受益）；图表原始数据以 `<table class="sr-only">` 供 SR 逐行读取。进度环：`role="progressbar"` + `aria-valuenow/min/max` + `aria-label`（「部署成功率 96%」） |
| 指标卡 | 数字容器 `aria-label` 完整读法：「总请求量 189 万，较上周上升 12.4%」——数字滚动动画期间 `aria-hidden` 包裹动画层，终值以 SR 专用文本呈现，避免播报滚动过程 |
| 表格 | `<table>` 真语义 + `<caption>`（「最近部署」）+ `<th scope>`；排序按钮 `aria-sort`；Badge 状态配 `visually-hidden` 文本（「运行中」Badge 本身是文本，无需补） |
| 分页器 | `<nav aria-label="分页">`，当前页 `aria-current="page"` |
| 装饰元素 | Hero 钴蓝光晕、浮层顶部受光边高光、shimmer 一律 `aria-hidden="true"` |
| 墨色面板（ink） | 页脚/CTA 为 `<footer>`/`<section>` 语义即可，**不用 role="presentation"**；确保屏幕阅读器正常进入阅读，不做特殊静音 |

### 5.4 `prefers-reduced-motion` 降级清单（穷举）

`@media (prefers-reduced-motion: reduce)` 下**逐项关闭**：

| # | 项目 | 降级为 |
|---|---|---|
| 1 | 章节进入 / 路由过渡的位移 | 仅 `opacity` 80ms（承 Phase 1R 总则） |
| 2 | 数字滚动（指标卡进页 600ms 计数） | 直接呈现终值，无动画 |
| 3 | 骨架屏 shimmer 循环 | 静态 `surface-raised` 色块（无平移循环） |
| 4 | 下拉 / 面板 scale 展开 | 仅 opacity 80ms，无 scale |
| 5 | Modal / 抽屉滑入位移 | 仅 opacity 80ms |
| 6 | 按钮按下 `scale(0.98)` | 取消 transform，仅颜色变化 |
| 7 | 开关滑块拉伸回弹 | 位移改为瞬时（80ms 内完成位移但不做拉伸形变） |
| 8 | 进度环 / 进度条扫过动画 | 直接跳到终值 |
| 9 | 图表数据线绘制动画 | 直接呈现完整曲线 |
| 10 | 锚点滚动（展示页） | 原生 `scroll-behavior: auto`（用户系统设置优先于平滑滚动） |

实现基线：全局 `@media (prefers-reduced-motion: reduce)` 兜底块 + 每个动效点单独覆盖；JS 驱动动画（数字滚动、进度）读 `matchMedia` 同步开关。

## 6. 交互状态规范（五态之外的补充态）

> 五态（default / hover / pressed / focused / disabled）视觉承 Phase 1R §6（浅色五态：hover 一律「加灰」不提亮）；本节只定义**补充态**的触发时机与呈现，颜色一律引用 Phase 1R token。

### 6.1 Loading 态

| 对象 | 触发时机 | 视觉呈现 |
|---|---|---|
| 按钮 loading | 异步操作发出（提交/刷新）且 >150ms 未返回 | 按钮内左侧出现 14px spinner（Primary：`--accent-contrast-text` 色；Secondary/Ghost：`--text-secondary` 色），文字保留并改为进行时文案（「保存中…」），按钮进 disabled 视觉（防重复点击）但**保留 `aria-busy="true"`**，完成 150ms 内撤除 |
| 表格骨架屏 | 数据请求 >300ms | §3.4 规格：表头实体 + 6 行 shimmer（1600ms 循环，暖黑 4% `rgba(23,24,28,0.04)` 扫过、底 `#FAFAF8`，Phase 1R 唯一值） |
| 指标卡骨架 | 数据请求 >300ms | 卡片轮廓（raised + border-default）+ 两条 shimmer（一条宽 60% 模拟数值、一条宽 40% 模拟标签） |
| 图表骨架 | 数据请求 >300ms | 面板轮廓 + 图表区一条 320px 高 shimmer 面板 |
| 顶栏刷新 | 点击刷新 | 图标按钮内图标替换为 14px spinner（`--text-secondary`），800ms 轮转一圈（唯一值），数据回来即停 |

### 6.2 空态（无数据）

| 对象 | 触发时机 | 视觉呈现 |
|---|---|---|
| 图表区空态 | 请求成功且数据集长度 = 0 | 居中：`inbox` 图标 24px `--text-tertiary` → H4 标题 primary → 一行说明 secondary → Ghost 按钮「配置数据源」（36px）；图标与文字间距 `--space-4`，整体区垂直居中于 320px 高度；空态卡保持白卡 + shadow-xs 规格不撤 |
| 表格空态 | 同上 | 同构：图标 `table-2` → 「还没有记录」→ 说明 → Primary 按钮「新建部署」；表头保留（结构可感知），数据区显示空态块 |
| 搜索无结果（命令面板内） | 过滤结果 = 0 | 面板内一行「未找到「关键字」相关结果」secondary，无按钮、无图标（轻量场景不堆元素） |

### 6.3 错误态

| 对象 | 触发时机 | 视觉呈现 |
|---|---|---|
| 输入框校验 | 失焦时校验失败 / 提交时校验失败 | 承 Phase 1R §6.2：描边 `--danger` + 3px `rgba(220,38,38,0.12)` 光晕 + 下方 12px/18px `--danger` 错误文案（与框距 6px）；错误文案带 `role="alert"`；修正后**输入即清除**（不等再次失焦） |
| 网络错误（数据区） | 请求失败且自动重试 1 次仍失败 | 图表/表格区内联错误块：白卡 + `--danger` 描边 1px + `--shadow-xs` + 左侧 `alert-triangle` 图标（`--danger`）+ 标题 primary + 说明 secondary + Secondary 按钮「重试」；错误底色用 `--danger-subtle` 仅限图标区衬底，**不用整块淡红底、更不用整页红**，错误限于区块 |
| 操作失败 toast | 用户主动操作（保存/部署/重试）失败 | Toast：白底（raised）+ `--shadow-md` + `border-strong`，左侧 3px `--danger` 竖条 + `--danger` 图标、标题 `--text-primary`、描述 `--text-secondary`；底部右上角（桌面）/顶部居中（<640）弹出，240ms 进入，停留 4000ms 自动关闭，悬停暂停计时；`role="alert"`（浅色 toast 改白卡+色条方案，不再用 tint 底整块铺色） |
| 操作成功 toast | 操作成功且**无专门结果界面**时 | 同 toast 规格，左竖条与图标改 `--success`；info（如概念页占位提示）用 `--info`（青绿，与钴蓝 accent 明确区分）；**成功 toast 必须可关**（右上 × 图标按钮 24×24） |

**Toast 使用上限**：同屏最多 1 条，新 toast 替换旧 toast（不做堆叠堆叠噪声）。

## 7. 微交互与反馈节奏

### 7.1 反馈时机总表（唯一值）

| 反馈 | 时限 | 规则 |
|---|---|---|
| hover / 按下视觉反馈 | **即时（80ms 内完成过渡）** | 时长用 `--duration-instant`；hover 用 `--duration-fast`（150ms）均可——**本表统一：hover 150ms、active 80ms** |
| 按钮点击 → loading 出现阈值 | **150ms** | 150ms 内返回的操作不闪 loading，直接走成功反馈 |
| toast 弹出 | **操作确定后 150ms 内**开始进入动画（240ms 完成） | 避免「点了没反应」 |
| 骨架屏出现阈值 | **300ms** | 请求 <300ms 完成则直接渲染内容，不闪骨架 |
| 表单校验反馈 | 失焦后 **150ms 内**显示错误 | 输入过程中不打断（不做逐键校验红框） |
| 数据就绪 → 内容呈现 | **150ms 淡出骨架 + 240ms 淡入内容** | 衔接不空窗 |
| 路由切换过渡 | 320ms 上限（承 Phase 1R） | Dashboard 内部 240ms |
| Toast 停留时长 | 4000ms 自动关闭，悬停暂停 | 关闭动画 240ms（standard） |
| 双击/重复提交防护 | 按钮 loading 期间整按钮禁用 | 即时 |

### 7.2 数字滚动规范（Dashboard 指标）

- 进页时从 0 计数至目标值，**600ms**，easeOutExpo（decelerate 的 JS 等效，承 Phase 1R §7.2）；mono + `tabular-nums`，位数不变（前导零不补、小数位固定位数）。
- 千分位分隔用**逗号**（`189,432`）；单位紧跟数字（`ms` / `%`）用 tertiary 小一号，不参与滚动。
- 环比 Badge 不滚动，在数字滚动完成后 80ms 淡入（150ms，decelerate）。

### 7.3 Dashboard 首屏进入编排（顺序与延迟）

原则：**先容器后内容、先总体后局部、总时长 ≤1200ms**（用户感知为「一次进入」而非连环动画）。所有延迟值为**首块开始的相对时刻**，动画时长均 ≤240ms：

| 顺序 | 元素 | 开始时刻 | 动画 |
|---|---|---|---|
| 1 | 侧边栏 + 顶栏 | 0ms | opacity 0→1 + translateY(8→0)，240ms，decelerate |
| 2 | 指标卡 1→4（依次） | 80 / 140 / 200 / 260ms（间隔 60ms） | opacity + translateY(8→0)，240ms，decelerate；数字滚动在各自卡片进场完成后 80ms 启动（600ms，easeOutExpo） |
| 3 | 面积图 | 320ms | 面板 fade 240ms；数据线绘制 320ms（自左向右描线，decelerate）+ 填充渐显 240ms |
| 4 | 进度环 + Top5 列表卡 | 380ms | 环：0→96% 扫过 320ms（decelerate）；列表项依次间隔 40ms 淡入 |
| 5 | 表格 | 440ms | 表头先入（240ms），数据行以 8 行为一组整体淡入（不逐行，避免长尾） |
| 6 | 页脚分页器 | 500ms | opacity 淡入 240ms |

- `prefers-reduced-motion`：全部编排降级为一次整体 opacity 80ms 淡入，数字/进度直接呈现终值。
- 编排仅在路由首次进入触发，同页内刷新不重播（只有数据本身按 §6.1 loading 态更新）。

### 7.4 图表交互微反馈

- 悬停数据点：竖向参考线（`--border-data`，3:1 可感知）+ tooltip（E2 浮层规格：白底 + shadow-md + border-strong，mono 数值 + 时间），跟随节流 16ms；离场 150ms 淡出。
- tooltip 不做位移弹跳，仅 opacity + 8px 位移（150ms，decelerate）。

## 8. 文案语气规范

### 8.1 语气三原则

1. **克制专业的陈述句**：像仪器面板的刻字，不像营销页的吆喝。删除一切「！」「～」「哦」「啦」。
2. **动词开头、动作明确**：按钮写「进入 Dashboard」不写「点击这里」；操作写「保存」不写「确定吗？」。
3. **错误归因于系统，出路交给用户**：错误文案 = 一句原因 + 一个动作（「数据加载失败，请检查网络 → 重试」），不指责用户输入。

### 8.2 场景语气表

| 场景 | 语气 | 示例 |
|---|---|---|
| 按钮 | 动词短语，2–6 字，不加句号 | 「进入 Dashboard」「新建报表」「重试」「配置数据源」 |
| 空态 | 不指责、给出口：标题陈述事实 + 说明一句 + 动作一个 | 「还没有数据 / 连接数据源后，这里将展示你的第一个报表 / 配置数据源」 |
| 错误（表单） | 指出具体字段问题，含修正方向 | 「请输入有效的邮箱地址」「名称不能超过 24 个字符」 |
| 错误（网络/系统） | 原因 + 动作，不用「抱歉」开头堆礼貌 | 「数据加载失败，请检查网络」+ 按钮「重试」 |
| 成功 toast | 一句话结果，不加感叹号 | 「报表已创建」「设置已保存」 |
| 占位提示（placeholder） | 说明用途，不写示例数据时不用引号 | 「搜索…」「输入邮箱地址」 |
| 确认类 | 问句 + 后果前置 | 「删除该部署？此操作不可撤销」+「删除 / 取消」 |

### 8.3 中文为主的标点与数字约定

| 项 | 约定（唯一值） |
|---|---|
| 句末标点 | 按钮、标题、导航、表头、Badge：**不加句号**；正文与说明句：加句号 |
| 引号 | 中文语境用直角引号「」，不用弯引号"" |
| 括号 | 中文语境全角（），纯英文代码/参数场景半角 () |
| 省略号 | 用「…」单字符，不用三个句号 |
| 数字 | 界面数字一律**半角阿拉伯数字** + mono + `tabular-nums`（承 Phase 1R 硬约束）；中文叙述里的数字同样半角，不写「 twelve 」式汉字数（版本号、日期、指标全部阿拉伯） |
| 千分位 | ≥5 位数用逗号千分位（`18,900`）；百分比保留 1 位小数（`12.4%`）；「万」单位仅中文叙述用（「18.9 万」），表格与指标卡用完整数字 |
| 单位 | 紧跟数字不留空格（`36ms`、`96%`）；存储单位大写（`MB`/`GB`） |
| 中英混排 | 中文与英文术语之间不手动加空格（承 Phase 1R §3.3，交给 text-autospace 或字体自然间距）；专有名词保持原文大小写（PRISM、Dashboard、Vite） |
| 时间 | 相对时间用于表格（「3 分钟前」），绝对时间用于 tooltip（`2025-06-01 14:32`，24 小时制） |
| 快捷键 | 用 `<kbd>` + 大写（`⌘K`、`Ctrl+K`） |

## 9. Phase 3 前端衔接注意点

1. **token 单一来源**：所有颜色 / 间距 / 字号 / 圆角 / 时长 / 缓动 / 阴影从 **Phase 1R（PRISM v2.0）附录 CSS 变量**取值，本文新增的数值仅限：`scroll-margin-top: 80px`、骨架阈值 300ms、按钮 loading 阈值 150ms、toast 4000ms、编排延迟表（§7.3）、spinner 800ms/圈、tooltip 节流 16ms。
2. **路由结构**：`/`（展示页，锚点）+ `/dashboard`（概念页），两页共享 Header/主题 token、各自独立 main 地标。
3. **优先实现顺序建议**：展示页骨架与锚点导航 → 色彩/字体/间距章（纯静态）→ 组件章（交互态）→ Dashboard 布局与响应式 → 编排与无障碍收尾。
4. **无障碍验收基线**：键盘走通两页全部功能（不用鼠标完成：导航、搜索、下拉、表格排序、抽屉）；焦点环全程可见；`axe` 扫描 0 严重违规。
5. **浅色新增注意点（PRISM 专属）**：
   - **hover 是加灰不是提亮**：一律 `--surface-hover-veil`（4% 暖黑）/ `--surface-active-veil`（7%），严禁沿用任何「加白」写法；
   - **ink 面板占比 <10%**：`--surface-ink` 仅页脚/CTA/键帽字三处，永远平面无阴影，白底页面不得出现第二块 ink；
   - **tint 上文字用 `--accent-deep`**：选中行/侧栏当前项/Badge 文字在 `--accent-subtle` 上一律 `--accent-deep`（6.5:1），`--accent` 只作 tint 上的图标与短标签；
   - **图表轴线/滑轨/参考线用 `--border-data`**（3:1），不用 border-default（太淡不达标）；
   - **focus 光晕 alpha 18%**（`rgba(46,91,255,0.18)`），不得沿用深色版 25%；
   - **语义 subtle 底上正文一律强调档**（`--success-strong` 等），图标可用默认档；
   - **info 语义色为青绿 `--info`**，与钴蓝 accent 拉开区分，涉及「提示类」反馈不得误用 accent 蓝。
6. **与 Phase 1R 的冲突仲裁**：若本文任何条目与 Phase 1R（PRISM v2.0）冲突，以 Phase 1R 为准并回报体验侧修订本文。
