## 8.1 加一个接口

不要从零写，用内置 AI Skill：

**Skill 路径**：`.agents/skills/coder-add-route/SKILL.md`

这个 skill 会帮你：
1. 在 `src/routes/` 下新建路由文件
2. 自动添加 utoipa 注解（生成 Swagger）
3. 在 `openapi.rs` 中注册路由
4. 生成单元测试 stub

> 💡 如果你是 AI Agent 操作，只需说"给 xxx-service 加一个 POST /xxx 接口"即可自动触发 skill。

## 8.4 跑某个服务的单元测试

```bash
# 方式 1：用 docker（推荐，避免本机缺少 cc linker）
node scripts/run-tests-docker.js iam-service

# 方式 2：直接 cargo（需本机有完整 Rust 工具链）
cd services/iam-service
cargo test --lib              # 单元测试
cargo test --test integration_test  # 集成测试
```

> 方式 1 会挂载源码和 cargo 缓存进 Docker 容器，首次编译慢，后续增量编译快。

## 8.5 跑 E2E 测试

```bash
# 确保基础设施已启动
docker compose -f infrastructure/docker-compose.yml up -d

# Smoke 子集（2 分钟，8 个 API + 2 个 UI 用例）
cd tests/e2e && pnpm test:smoke

# 全量 API 测试（5 分钟）
pnpm test:api

# 全量 UI 测试（10 分钟，需前端容器）
docker compose -f infrastructure/docker-compose.yml up -d frontend
pnpm test:ui
```

## 8.5.1 启动 / 关闭 Docker 环境（标准顺序）

`infrastructure/docker-compose.yml` 是 **include 入口**（仅 4 行），自动合并 infra 与业务 services。observability 是**独立 overlay**，按需启动。

**启动**（顺序无关，但推荐按依赖层级）：

```bash
# 1. 主栈（基础设施 + 业务服务 + 可观测性，一把起 21 个容器）
docker compose -f infrastructure/docker-compose.yml up -d
```

> 容器内部启动顺序由 `depends_on: condition: service_healthy` 自动编排：
> `mysql/redis/consul (healthy) → token-service → api-gateway → frontend`，
> 其它服务（iam / notification / audit / prue_backend）与 token-service 并行起。

**只起基础设施**（业务服务本地 `cargo run` 时常用）：

```bash
docker compose -f infrastructure/docker-compose.yml up -d mysql redis consul
```

**关闭**（先 overlay 再主栈，反向顺序）：

```bash
docker compose -f infrastructure/docker-compose-observability.yml down
docker compose -f infrastructure/docker-compose.yml down
# 加 -v 清数据卷（MySQL 数据会被清空）
```

**查看与日志**：

```bash
docker compose -f infrastructure/docker-compose.yml ps           # 查看状态
docker compose -f infrastructure/docker-compose.yml logs -f      # 跟随全部日志
docker compose -f infrastructure/docker-compose.yml logs -f token-service   # 单服务
```

## 8.6 改 api-gateway 路由 + 热加载

```bash
# 1. 编辑路由配置
vim infrastructure/config/api-gateway/routes/xxx.router.toml

# 2. 热加载（无需重启）
curl -X POST http://localhost:3000/__admin/reload

# 或用 SIGHUP
kill -HUP $(pgrep api-gateway)
```

> 路由配置文件格式请参考：[`docs-site/guides/api-gateway-routing.md`](../guides/api-gateway-routing.md)

## 8.7 PR 前必跑的三条 CI Gate

在提交代码前，确保以下检查全部通过：

```bash
# 1. 服务规范检查（8 项必检）
node scripts/check-service-standard.js

# 2. 契约规范检查（错误码、权限码、OpenAPI）
node scripts/check-spec.js

# 3. 契约代码一致性检查
cd tests/contracts && node scripts/contracts-gen.js --check
```

如果以上任何一条报错，请先修复再提 PR。

---

## 8.8 重新生成 OpenAPI 规范

如果改了接口注解但没重新生成 yaml，CI 会失败：

```bash
scripts/dump-openapi-specs.sh
```

这会自动更新 4 个服务的 `openapi.yaml` 文件。生成后记得提交。
