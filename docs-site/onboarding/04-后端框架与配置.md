# 04. 后端框架与配置

> 读完这一章你会知道：① 每个框架在项目里做什么；② 服务配置文件每个字段什么意思；③ 环境变量怎么覆盖配置；④ 改了配置怎么生效。

---

## 4.1 主框架对照表

本项目不是从零造轮子，而是把多个成熟框架按职责拼在一起：

| 框架 | 职责 | 一句话说明 | 官网 |
|------|------|-----------|------|
| **Axum** | HTTP 路由 + 中间件 | 处理请求进来 → 路由匹配 → 中间件链 → Handler | https://docs.rs/axum |
| **Tokio** | 异步运行时 | 让 Rust 能同时处理成千上万个请求不阻塞 | https://tokio.rs |
| **SQLx** | 数据库 | 编译期检查 SQL 语句（写错 SQL 编译就报错） | https://github.com/launchbadge/sqlx |
| **Utoipa** | OpenAPI | 从 Rust 代码自动生成 Swagger 文档 | https://github.com/juhaku/utoipa |
| **Tracing** | 结构化日志 | 生成带 trace_id 的日志，可跨服务串联 | https://docs.rs/tracing |
| **serde** | 序列化 | JSON ↔ Rust 结构体自动转换 | https://serde.rs |
| **testcontainers** | 集成测试 | 在测试里自动启动 MySQL/Redis Docker 容器 | https://github.com/testcontainers/testcontainers-rs |
| **governor** | 限流 | 网关层的令牌桶限流算法 | https://github.com/boinkor-net/governor |

## 4.2 服务配置文件详解

每个 Rust 服务都有自己的配置文件，以 `iam-service` 为例：

**文件路径**：`services/iam-service/config/config.yaml`

```yaml
app:
  name: iam-service
  host: 0.0.0.0
  port: 8080

database:
  url: mysql://root:rootpass@mysql:3306/superpowers?ssl-mode=DISABLED
  max_connections: 20
  min_connections: 5

redis:
  url: redis://redis:6379/0
  ttl_sec: 86400

jwt:
  private_key_path: /app/keys/private.pem
  public_key_path: /app/keys/public.pem
  access_token_ttl_minutes: 15
  refresh_token_ttl_days: 7

consul:
  host: consul
  port: 8500
  service_name: iam-service
```

### 字段逐条解释

| 字段 | 含义 | 常见改法 |
|------|------|---------|
| `app.name` | 服务名，用于日志和 Consul 注册 | 一般不改动 |
| `app.host` | 监听地址 | `0.0.0.0` 表示监听所有网卡；本地开发可改成 `127.0.0.1` |
| `app.port` | 内部监听端口 | 统一 8080，不改 |
| `database.url` | 数据库连接串 | 改主机名、密码、库名 |
| `database.max_connections` | 连接池最大连接数 | 高并发时调大 |
| `database.min_connections` | 连接池最小连接数 | 低负载时保持 |
| `redis.url` | Redis 连接地址 | 改主机名、端口、DB 号（`/0` 是 DB 0） |
| `redis.ttl_sec` | Redis 默认过期时间（秒） | 86400 = 1 天 |
| `jwt.private_key_path` | JWT 签名私钥路径 | 容器内固定为 `/app/keys/` |
| `jwt.public_key_path` | JWT 验签公钥路径 | 同上 |
| `jwt.access_token_ttl_minutes` | Access Token 有效期 | 默认 15 分钟 |
| `jwt.refresh_token_ttl_days` | Refresh Token 有效期 | 默认 7 天 |
| `consul.host` | Consul 地址 | Docker 内用 `consul`，宿主机用 `localhost` |
| `consul.port` | Consul 端口 | 默认 8500 |
| `consul.service_name` | 注册到 Consul 的服务名 | 与 `app.name` 一致 |

> 💡 不同服务的 `config.yaml` 字段大同小异，主要区别在于 `app.name` 和 `database.url` 的库名。

## 4.3 环境变量优先级

配置生效的优先级（**高 → 低**）：

1. **环境变量**（如 `DATABASE_URL`）— 最高，覆盖一切
2. **`config.yaml`** — 次高，日常开发主要改这里
3. **代码默认值** — 兜底，一般不写死

### 常用环境变量

| 变量 | 作用 | 默认值 | 在哪用 |
|------|------|--------|--------|
| `RUST_LOG` | 日志级别 | `info` | 所有服务 |
| `DATABASE_URL` | 数据库连接串 | 读 config.yaml | 有 DB 的服务 |
| `SWAGGER_ENABLED` | 是否启用 Swagger UI | `true` | 有 Swagger 的服务 |
| `CONSUL_ADDR` | Consul 地址 | `http://localhost:8500` | 有 Consul 的服务 |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | OTel 收集器地址 | — | 4 个启 OTel 的服务 |

> 💡 本地开发时直接在终端里 `export RUST_LOG=debug` 临时调日志级别，改完 `cargo run` 即生效，不用改 yaml。

## 4.4 修改配置后如何生效

### api-gateway 路由配置（支持热加载）

路由配置在 `infrastructure/config/api-gateway/routes/*.router.toml`，修改后有两种方式生效：

```bash
# 方式 1：SIGHUP 信号（Linux / macOS）
kill -HUP $(pgrep api-gateway)

# 方式 2：HTTP POST 到 admin 端点
curl -X POST http://localhost:3000/__admin/reload
```

> 方式 2 更通用，Windows WSL2 也支持。

### 其他服务配置

**不支持热加载**，需要重启服务：

```bash
# Ctrl+C 停止，再重新 cargo run
cd services/iam-service && cargo run
```

### 限流配置

限流在 `infrastructure/config/api-gateway/rate-limits.toml`：

```toml
[defaults]
requests_per_second = 100
burst = 200

[routes."/v1/iam/auth/login"]
requests_per_second = 5
burst = 10
```

修改后需重启 api-gateway：

```bash
kill -HUP $(pgrep api-gateway)
```
