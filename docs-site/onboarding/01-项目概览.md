# 01. 项目概览

> 读完这一章你会知道：① 项目一句话定位；② 微服务架构长什么样；③ 每个服务做什么；④ 核心技术栈有哪些。

---

## 1.1 一句话定位

**coder-micro-services** 是一个基于 Rust 的低内存微服务平台模板。**框架不随附前端控制台**（原 PRISM console 已移除），前端在业务仓中经 `packages/` 与 `sdk/` 接入。

> 不是从零造轮子，而是用成熟框架（Axum、SQLx）搭好后端骨架，让团队能直接在上面写业务接口。

---

## 1.2 微服务架构

```
                              ┌──────────────────┐
     浏览器 / SDK ───────────►│   api-gateway    │  :3000  (JWT + 限流 + 追踪)
                              └────────┬─────────┘
                                       │ HTTP 直连（Authorization: Bearer <jwt> 透传）
                  ┌────────────────────┼─────────────────────┐
                  ▼                    ▼                     ▼
           token-service          iam-service         notification-service
           :8082 (host)           :9081 (host) / 8081  :8083 (host)
           → iam:8081                                       (WebSocket 推送)
                  │                    │                     │
                  ▼                    ▼                     ▼
                MySQL                MySQL                 MySQL
                                                        + WS /ws
                  ┌────────────────────┼─────────────────────┐
                  ▼                    ▼                     ▼
           prue_backend          audit-service        config-service  file-service
           :8087 (host)          :8084 (host)         :8085 (host)    :8086 (host)
                SQLite/MySQL         MySQL                MySQL          MySQL
```

| 服务 | compose host 端口 | 容器内端口（跨服务调用） | 职责 | 依赖 |
|------|------------------|------------------------|------|------|
| **api-gateway** | 3000 | 3000 | JWT 验证、Redis 黑名单、限流、追踪上下文注入、路由转发 | Consul（服务发现） |
| **token-service** | 8082 | 8082 | 签发/刷新/吊销 JWT、JWKS 暴露 | MySQL / Redis / Consul |
| **iam-service** | 9081¹ | 8081 | 身份认证 + RBAC 权限 + 部门树 | MySQL / Consul |
| **notification-service** | 8083 | 8083 | 公告 + WebSocket 推送 | MySQL / Redis / Consul |
| **prue_backend** | 8087 | 8087 | 纯管理后台菜单配置后端 | SQLite / MySQL / Consul |
| **audit-service** | 8084 | 8084 | 审计日志 | MySQL / Consul |
| **config-service** | 8085² | 8081 | 配置中心 | MySQL / Consul |
| **file-service** | 8086² | 8082 | 文件存储 | MySQL / Consul |

> ¹ **iam-service compose host 端口 9081** 是 Phase 5-A mesh 时代 sidecar 外端口残留（容器内一直是 8081），待 spec §7.3 统一到 `8081:8081`。
>
> ² **config-service / file-service 的 host 端口 8085 / 8086** 是 Phase 5-A-2 spec §7.3 引入的消歧（容器内与 iam / token 同端口，靠 host 端口区分），不影响 gateway / 跨服务调用（走容器内端口）。
>
> 跨服务调用走**容器内端口**（`http://iam-service:8081` 等），由 Docker `superpowers` 网络 DNS 解析；host 端口只用于宿主机 `curl http://localhost:908x/swagger-ui` 之类开发联调。详见 [`docs-site/guides/service-registration.md`](../guides/service-registration.md) 与 [`docs-site/user-manual/11-reference.md` §11.5](../user-manual/11-reference.md#115-服务端口速查phase-5-a-2-之后)。

## 1.3 前端集成（框架不随附前端）

PRISM console（原 `frontend/` 目录）已于 2026-10 从本框架移除。前端项目在各自业务仓中，通过以下方式接入 api-gateway（:3000，唯一公共入口）：

| 集成方式 | 说明 |
|------|------|
| `packages/@digua/contracts` | 错误码 / 权限码 / OpenAPI 客户端 TS 产物（仓库顶层，npm 包） |
| `packages/@digua/http` | 框架无关 HTTP 客户端：token 注入 / 单飞刷新 / 错误码转文案（仓库顶层，npm 包） |
| `sdk/java`、`sdk/rust` | 服务端 SDK；C# SDK（`sdk/dotnet`）规划中 |

两个 npm 包发布到私有 registry `http://npm.kudi.repos/`（根目录 `pnpm run packages:publish`，校验用 `pnpm run packages:check`）。

## 1.5 服务规范（8 项必检）

每个 Rust 服务都必须满足（CI 会检查）：

- Dockerfile ✅
- AGENTS.md ✅

- tests/ 目录 ✅
- `/health` 端点 ✅
- `/metrics` 端点 ✅
- migrations/ 目录 ✅
