# 09. 出问题怎么办

> 读完这一章你会知道：① 卡住时按什么顺序自检；② 怎么提一个有用的 bug 报告。

---

## 9.1 故障自检清单

遇到问题时，按以下顺序逐项检查，**不要跳过**：

### 基础设施层

- [ ] Docker Desktop 是否已启动？
- [ ] `docker ps` 是否能看到 MySQL / Redis / Consul 容器？
- [ ] 容器状态是否为 `Up`？如果不是，`docker logs <容器名>` 看报错
- [ ] 端口是否被占用？`lsof -i :3306` / `lsof -i :6379` / `lsof -i :8500`

### 服务层

- [ ] 服务进程是否在运行？`ps aux | grep <服务名>`
- [ ] 服务日志里是否有明显报错？`cargo run` 终端或 `docker logs`
- [ ] Consul 里是否注册了该服务？http://localhost:8500
- [ ] 数据库连接是否正常？`mysql -h 127.0.0.1 -uroot -prootpass -e "SELECT 1"`

### 配置层

- [ ] `config.yaml` 里的数据库地址、Redis 地址是否正确？
- [ ] 环境变量是否覆盖了配置？`echo $DATABASE_URL`
- [ ] sqlx-data.json 是否是最新的？`cargo sqlx prepare`

### 网络层

- [ ] 服务端口是否通？`curl http://localhost:9081/health`（iam-service compose host 端口）
- [ ] api-gateway 路由是否配置？`ls infrastructure/config/api-gateway/routes/`
- [ ] 限流是否触发？`cat infrastructure/config/api-gateway/rate-limits.toml`

### 代码层

- [ ] 最新代码是否已 pull？`git pull origin main`
- [ ] 依赖是否最新？`pnpm install` / `cargo update`
- [ ] 是否有未提交的本地修改影响行为？`git status`

## 9.3 Bug 报告模板

如果自检后仍无法解决，请按以下模板提交 bug 报告：

```markdown
## 环境
- 运行环境：本地开发 / 测试 / 生产
- 操作系统：Windows / macOS / Linux
- 分支：`main` 或具体分支名
- 最近修改：你改了什么代码/配置？

## 操作步骤
1. 执行了 `xxx` 命令
2. 打开了 `xxx` 页面
3. 点击了 `xxx` 按钮

## 期望结果
xxx

## 实际结果
xxx（附完整报错信息/截图）

## trace_id
X-Trace-Id: xxx（如有）

## 相关日志
```
（粘贴最近 20 行相关服务的日志）
```

## 已尝试的排查步骤
- [ ] 已检查容器状态
- [ ] 已检查服务日志
- [ ] 已重新生成 sqlx-data.json
- [ ] 其他：xxx
```
