
## 6.3 启动 dev server

```bash
# 在项目根目录
pnpm --filter @coder/frontend run dev
```

> 默认端口 **8848**，浏览器打开：http://localhost:8848

> 💡 不需要 `cd frontend/`，因为前端是 pnpm workspace 成员，`--filter @coder/frontend` 会自动定位到 `frontend/` 目录。

如果端口被占用，可在 `frontend/.env` 中修改：

```
VITE_PORT = 8848
```

## 6.4 与后端联调

前端的 Vite 代理配置在 `frontend/vite.config.ts:18-24`：

```ts
proxy: {
  "/api": {
    target: "http://127.0.0.1:3000",  // ← api-gateway
    changeOrigin: true,
    rewrite: (p: string) => p.replace(/^\/api/, "")
  }
}
```

这意味着：

| 前端请求 | 实际到达 |
|---------|---------|
| `GET /api/iam/users` | `http://127.0.0.1:3000/iam/users`（api-gateway） |
| `POST /api/auth/login` | `http://127.0.0.1:3000/auth/login`（api-gateway） |

> 前端不需要关心具体哪个服务处理请求，统一走 `/api` → api-gateway → 各服务。

### 改代理目标（如后端端口变了）

编辑 `frontend/vite.config.ts`，修改 `target` 后保存，Vite 会自动热重载，无需重启。

## 6.5 登录态存储

登录态由 `frontend/src/utils/auth.ts` 管理，核心逻辑：

```typescript
// Token 存在 Cookie 中（multiple-tabs 支持多标签页共享）
const TokenKey = "authorized-token";

// 用户详情存在 localStorage 中
const userKey = "user-info";

export function getToken() {
  return Cookies.get(TokenKey)
    ? JSON.parse(Cookies.get(TokenKey))
    : storageLocal().getItem(userKey);
}
```

| 数据 | 存储位置 | 用途 |
|------|---------|------|
| `accessToken` + `refreshToken` | Cookie (`TokenKey`) | 请求鉴权头 |
| `username` / `roles` / `permissions` | localStorage (`userKey`) | 页面渲染（用户名、菜单权限） |
| `multiple-tabs` | Cookie | 多标签页间同步登录态 |

### Token 刷新机制

- `accessToken` 有效期 15 分钟（后端配置 `jwt.access_token_ttl_minutes`）
- 过期前自动调用 `refreshToken` 接口换取新的 `accessToken`
- 刷新逻辑在 `frontend/src/store/modules/user.ts` 的 `loginByUsername` action 中

## 6.6 修改菜单

前端菜单不是写死的，而是从后端 `prue_backend` 服务动态拉取的：

1. 登录成功后，前端请求 `GET /api/prue/menu`（或类似路径）
2. 返回菜单树结构
3. 前端渲染侧边栏

> 修改菜单内容需要改 `prue_backend` 的数据库或接口返回，不是改前端代码。

## 6.8 调试技巧

1. **Vue DevTools**：浏览器安装 [Vue DevTools](https://devtools.vuejs.org/) 插件，可查看组件树、Pinia 状态、事件
2. **Network 面板**：看请求路径、状态码、响应体，特别关注响应头里的 `X-Trace-Id`
3. **Console**：前端报错先看控制台，Axios 拦截器会统一处理错误提示
4. **跨服务追踪**：拿到 `X-Trace-Id` 后，去 Jaeger（http://localhost:16686）搜索，看后端各服务处理过程
